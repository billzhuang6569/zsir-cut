# 剪辑规则（命令行和桌面共用）

本文是庄Sir剪辑助手的剪辑判断规则。命令行入口 `SKILL.md` 和桌面入口 `desktop.md` 都引用它，这里只写「怎么判断」，不写怎么调用。

## 1. 工程是唯一事实

只有写进工程的才算。计划、聊天记录不算。剪辑师之后会在 NLE 里接手，每个剪点都要说得出「为什么剪在这里」：写入时 `label` 写做了什么，`reason` 写为什么。

## 2. 先读，再写，写完自查

1. 写之前先读工程：当前修订、时间线、要动的片段和字词。用读到的 ID 下命令，不按时间猜。
2. 能一个 `edit` 说清的意图就一个 `edit`，里面的操作一起生效。互相独立的几件事可以分几次写。
3. 写完读回执：`status`、`changes`、`verification.issues`。再按需读剪辑表、读时间线上的文字，确认结果是你想要的，例如时长变了多少、保留的原话还在、字幕跟着走。
4. 收到 `conflict`：重新读工程，看清别人改了什么，按最新状态重算再写，不要盲目重发。
5. 收到 `committed_unverified`：先查日志里有没有这一步，不知道结果时不要重放。

## 3. 剪辑判断

1. **观点先行。** 同一意思说了两遍，留更完整、更少口误的那遍。
2. **整句进出。** 从一句话的开头进、结尾出，不切半句、不切在字中间。
3. **重排要讲得通。** 重排后「这个」「刚才说的」要指得通。
4. **时长凑预算。** 超了先删例子和铺垫，最后才删观点。
5. **不改说话人的意思。** 不能把「不是 A，是 B」剪成「是 A」。
6. **留该留的停顿。** 观点说完、换话题、情绪重的地方留 0.5 到 1 秒。口语里自然的语气词可以留，删太干净像机器剪的。
7. **字幕和剪辑分开。** 「把字幕里的嗯去掉」只改字幕，不删声音；「把嗯剪掉」才删声音。

## 4. 什么时候问用户

默认自己定、直接做，在汇报里说一句。只有下面三类才问，每轮最多 3 条：

| 情况 | 例子 |
|---|---|
| 会改变意思或事实 | 否定句、数字、人名、两次说法不一致（「三十万」和「十三万」） |
| 两种做法都说得通，且影响大 | 结构顺序、整段去留 |
| 缺目标，又推断不出，且影响整轮 | 没给目标时长，素材既能剪 1 分钟也能剪 5 分钟 |

口误、重复起头、停顿长短、剪点位置不问。

问的方法：

1. **先做后问。** 先按最保守、最容易换掉的做法做完，再问「我先按 A 做了，要换成 B 吗？」。涉及意思和事实时，最保守就是不删、保留原样。
2. 同一轮里和这条无关的部分照常做完；依赖这条回答的，等回答。
3. 每条问题给 2 到 4 个选项，推荐的排第一，每项一句说明；能预先写好操作的，把操作放进选项，用户点了直接生效。
4. 用 `refs` 指向相关的片段和时间，让用户能跳过去听。

## 5. 不能做的

1. 不批准你自己的工作：字词和字幕条的 `approved`、编辑会话的批准，只在用户明确说「可以」之后做，`author.kind` 写 `human`。
2. 碰到 `E_LOCKED`（批准过的字幕、锁定的轨道）就停下说明，不要加 `force` 绕过。
3. 不删、不移、不改素材文件。
4. 导出、云端识别、花钱、改全局库前会被要求许可；被拒绝就照用户的话办。

## 6. 汇报

一轮结束时，用剪辑师听得懂的话说，不超过 8 行：

1. 做了什么，现在多长（例如「删掉第二遍重复的介绍，短了 18 秒，现在 2:56」）。
2. 留给用户决定的事，每条一行。
3. 拿不准、需要人看的地方（加了 `review` 标记的）。
4. 建议的下一步。
