# 字幕

字幕不是另做的 SRT，而是工程里的数据：识别出的字词带着源时间，跟着剪辑走。删掉一段话，它的字幕自动消失；挪动一段，字幕跟着挪。你要做的是把字改对、把断句调顺，而不是对时间轴。

## 1. 前提

- 工程有字幕轨。用 `create_project` 的 `subtitles` 建的工程已经有 `trk_sub1`；旧工程没有时，用字幕域的 `add_style` 加 `add_subtitle_track` 建，承载轨写主说话人的音频轨。
- 母稿语言与字幕轨 `language` 写法完全相同。校验报 `W_SUB_NO_TRANSCRIPT` 就是这里对不上，字幕会是空的。
- 粗剪已经批准进主工程。字幕校对在剪辑定稿后做，省得改了又被剪掉。

## 1.1 抽专有名词

识别完成后、校字之前做一次：

1. 通读文稿和 `recognition.reference_text`，挑出专有名词：品牌、产品、人名、公司和机构、地名、行业术语。普通词、口语、数字不算。
2. 识别错的名词按正确写法记，例如文稿里是「斗包」、上下文明显是「豆包」，记「豆包」，再按第 2 节改字。
3. 用 `set_recognition` 把它们追加进 `terms`（保留原有的，不要覆盖用户加的）。在本工程文稿里出现 2 次及以上的，内核会自动收进本机的全局名词库，以后的工程识别时也能认出来。
4. 告诉用户抽了哪些词，一行列完。用户说哪个不对，就从 `terms` 里删掉。
5. 名词改动很多（5 个以上识别错的）时，问用户要不要带着新名词重新识别。

## 2. 校字

1. `read_transcript` 按时间线读（`timeline_id`），只校会出现在成片里的字。每行开头的方括号里是字幕条 ID 和首尾字词 ID。
2. 对照词表逐条改：
   - 识别错的字、错的品牌名人名：`edit_text`，`from_token` 到 `to_token` 换成正确文字。原来听到的内容会自动存进 `heard`，不会丢。
   - 数字统一写法：采访里的数字按词表或用户偏好统一，例如「百分之六十」写成「60%」。拿不准用户偏好就问一次，然后全片统一。
   - 口头禅和语气词：字幕里可以不显示，但画面里还在说。用 `hide_tokens` 隐藏，不要用剪辑去删。
3. 听不清、可能说错的地方（尤其是数字、人名、专有名词），不要猜。加 `review` 标记，写明「12 分 03 秒：识别为『三千万』，请核对」。标记是剪辑域操作，单独一个请求。
4. 每批改动一个 `edit` 请求，按段落分批，方便撤销。

## 3. 断句

识别出来的字词没有标点，规则只能按停顿和字数切。字幕要一出来就是好的，所以识别完必须跑一轮按意思断句（`subtitle-rules.md` 第 10、11 节）。

**桌面版里不用你做**：宿主进程在识别完成后自动整理，状态显示「整理字幕…」。你识别完等它结束再看字幕，不要自己再跑一遍。

**命令行和 MCP 里你来做**：

1. 识别完，读母稿的字词（第 2 层 `text` 非空的），按停顿 ≥ 0.7 秒分块，每块不超过 600 个字词。
2. 每块决定在哪些字词后面断开；开了去除水词（`recognition.remove_fillers`）时，再挑出要隐藏的口头禅和重复。
3. 一个 `edit` 批次提交：先 `hide_tokens`，再一个不带 `range`、带全部 `cut_after` 的 `resegment`，`label` 写「AI 整理字幕」。
4. 之后改了字，对改动范围跑不带 `cut_after` 的 `resegment`；改动较大时对这一段重新给 `cut_after`。

断句的要求：

- 一条字幕是一个完整的意群，读起来不用等下一条才明白。中文目标每条 6 到 16 个字；内核会保证不超过一行 16 个字。
- 在分句、主题和评论、并列成分之间断。「但是、然后、所以、因为、如果、而且、就是说」这类连接词放在下一条开头。
- 不在「的、地、得、和、与、在、是、把、被、给、对、让、很、都、也、就、这个、一个」这类字后面断。
- 不在「了、着、过、吗、呢、吧、啊、们、上、里、时」这类字前面断。「做了｜是你」要断在「做了」后面，而不是「是」后面。
- 不拆名词、人名、品牌、数字和单位：「抖音」「两万多个」「二十四小时」要在同一条里。
- 每条都要是说完的一句或一个完整成分：不以「需要、可能、就是、能够、可以、要、会、去、帮我们、给到、这么一个」这类没说完的词结尾；不要只有「可能就是」「然后他们只需要」这种半截话，和后面放在同一条，到 16 个字为止。少于 6 个字的条，除非本身是独立的一句（「对」「好的」「效率不够高」），就和前后合在一起。
- 不以「是」结尾；「的」只在「是……的」句式或句子真正说完时放在结尾。
- 先按这些要求断一遍，再逐条检查结尾和开头，然后输出。
- 去除水词开着时，隐藏单独出现的「呃、嗯、啊、哎」和紧挨着的重复（「上传上传」只留一个、「开始开始」只留一个）。有意义的语气词（「好啊」「对吧」）不动。不要隐藏专有名词，一块里隐藏的不超过两成。

例子（没有标点的原文）：

> 所有的点位加起来可能有两万多个很多的脏活全部让豆包工作去做了是你要真正去使用之后你才能够去感受到

好的断法：

> 所有的点位加起来 ｜ 可能有两万多个 ｜ 很多的脏活 ｜ 全部让豆包工作去做了 ｜ 是你要真正去使用之后 ｜ 你才能够去感受到

看完 `verification.issues`：

- `W_SUB_CPS`：一条字太多、念得太快。可以在语义停顿处再断，或者隐藏不影响意思的虚词。
- `W_SUB_SHORT`：显示太短。如果和相邻条语义上是一句，`merge_cues` 合并。
- `W_SUB_TOO_WIDE`：一个词比一行还宽，通常是很长的英文名或网址，告诉用户。
- `W_SUB_PASS_FALLBACK`：桌面版整理时有一段退回了规则断句，告诉用户原因。

## 4. 片头标题和说明字

人名条、地点、片头标题这类不是说话内容的字，用 `add_free_cue` 加独立字幕条，带自己的序列时间。不要塞进母稿。

## 5. 交给人确认

- 不要把字词或字幕条设为 `approved`，那是人看过之后的状态。
- 给用户列出：改了多少处，哪些是按词表改的，哪些是你判断的，哪些加了 `review` 标记。
- 用户确认某一段没问题后，按用户的话用 `set_token_state` 或 `set_cue` 设为 `approved`，`author.kind` 写 `human`。之后重新识别或自动断句都不会再改它们。
