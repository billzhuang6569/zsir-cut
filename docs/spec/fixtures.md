## 3. 合成素材

### 3.1 素材清单

29.97 素材的帧数是时长乘以帧率后向上取整，例如 120 秒是 3597 帧。所有视频统一 960×540、方形像素，H.264 全帧内编码（每帧都是关键帧，保证任意帧定位精确），封装为 `.mov`。音频 48 kHz、24 bit PCM。

### 3.2 画面

每一帧烧录以下内容，位置固定：

- 左上：素材数字 ID，例如 `A · 1`。
- 右上：源帧号，6 位补零，从 0 开始。
- 左下：源时码，按素材的起始时码和帧率计算，29.97 素材按丢帧格式显示。
- 正中：台词脚本里这一刻「正在说」的字词，没有就留空。只有素材 A 有。
- 包含整秒时刻的那一帧背景变白，文字和底部条码照常绘制：第 k 秒对应帧号 `floor(k × 帧率)`。25 帧素材里就是每秒第 0 帧；29.97 素材里白帧会逐渐落在「秒」的后半段，这是有意的。白帧与音频的同步脉冲对应。
- 底部 16 像素是机器条码：48 个 20×16 的格子，黑为 0、白为 1，从左到右依次是 16 位素材数字 ID、24 位源帧号、8 位校验（前 40 位按字节求和取低 8 位）。宿主渲染比对和生成器自检都读这一条，不靠文字识别。

可变帧率素材 24 的帧号按实际解码顺序计数。静帧图片 22 只有左上 ID 和底部条码，帧号固定为 0。透明图形 23 的画面中央 480×270 图形块、角上的文字和底部条码不透明，其余区域完全透明。

### 3.3 声音

- **声道 0：同步脉冲加台词音。** 在每个整秒时刻（0 s、1 s、2 s……）开始一个 2 kHz、时长 40 ms 的脉冲。脉冲按真实秒数放置，不跟帧网格走，所以 25 帧和 29.97 帧两套素材的声道 0 完全相同，外录音频能同时和两套对齐。素材 A 在每个字词的开始时刻加一个 40 ms 的短音，频率 `600 + 40 × (字词序号 mod 20)` Hz，最高 1360 Hz，不会和脉冲混淆。
- **声道 1：素材识别音。** 持续的低电平正弦，频率 `200 + 10 × 素材数字 ID` Hz。听到或测到频率就知道是哪个素材。
- 外录音频 21 只有声道 0，比素材 A 早 2 秒开机：它的第 2 秒对应素材 A 的第 0 秒，之后内容与素材 A 的声道 0 完全相同，前 2 秒是静音。正确对齐后脉冲应逐样本重合。

### 3.4 生成器要求

- 命令：`pnpm fixtures:gen` 生成全部素材到 `fixtures/.media/`，并写出 `fingerprints.json`（每个文件的路径、大小、`sampled-sha256-v1` 指纹）。
- 命令：`pnpm fixtures:bind` 把 `fixtures/projects/` 里的工程复制到 `.media/projects/`，用 `fingerprints.json` 填入真实的大小和指纹，并把路径改成相对副本位置。
- 命令：`pnpm fixtures:check` 自检：每个视频抽首帧、末帧和 5 个随机帧，读回机器条码，ID 和帧号必须与预期一致；检查每个文件的帧率、时长、起始时码、声道数与 3.1 表一致；检查每个脉冲的起点都落在对应白帧的时间区间内。
- 命令：`pnpm fixtures:relocate <新根目录>` 把素材整体移到另一个目录，用来测「移盘后重链接」。
- 固定一个 ffmpeg 版本，写进 `fixtures/synth/TOOLS.md`。不同 ffmpeg 版本生成的文件字节可以不同，所以验证靠条码和元数据，不靠文件哈希。
- 全部生成在一台 Apple Silicon Mac 上 2 分钟内完成，总大小不超过 300 MB。

## 4. 台词脚本

`fixtures/synth/script.json` 给出素材 A 从 0 到 120 秒的全部字词：每个字词的序号、文字、开始和结束时间（毫秒）、所属句子。生成器按它烧录画面中央的字和声道 0 的短音，标准工程按它写字幕母稿。所以字幕在标准工程里的「正确答案」是已知的，不依赖识别引擎。

脚本覆盖：品牌词（zsir-cut、Final Cut Pro、DaVinci Resolve）、数字和单位、中英混说、句间停顿；并保证有一个字词正好跨过标准工程里的一个剪点。

## 5. 标准工程

三个工程，结构相同，只是帧率和时码不同：

| 文件 | 时间线帧率 | 时码 | 用的素材 |
|---|---|---|---|
| `std-25.zcut.json` | 25 | 01:00:00:00，不丢帧 | 1、2 和全部共享素材 |
| `std-2997-df.zcut.json` | 30000/1001 | 01:00:00;00，丢帧 | 11、12 和全部共享素材 |
| `std-2997-ndf.zcut.json` | 30000/1001 | 01:00:00:00，不丢帧 | 同上 |

29.97 工程里，共享的 25 帧素材 31、32、透明图形 23 和可变帧率素材 24 就是混合帧率的情况。

每个工程覆盖下表全部情况。片段的具体帧数以工程文件为准。

| 编号 | 情况 | 对应的验收点 |
|---|---|---|
| S1 | 两条视频轨、四条音频轨、序列起始时码非零 | 轨道顺序、时码 |
| S2 | 同一素材 A 用了三次，入出点各不相同 | 三层身份、重复使用 |
| S3 | J cut 和 L cut | 同一次使用的视音频同步 |
| S4 | 视频轨上的空隙 | 空隙不被吞掉 |
| S5 | 带余量的叠化 | 转场 |
| S6 | 恒定 200% 变速、倒放 | 时间映射 |
| S7 | 分段变速：100%、50%、定格、200% | 时间映射，字幕在定格段不投影 |
| S8 | 平滑速度坡度 | 预期近似，必须出现在损失报告里 |
| S9 | 缩放、旋转、位移、裁切 | 变换 |
| S10 | 恒定增益 | 音量 |
| S11 | 静帧图片、透明图形 | 非视频素材 |
| S12 | 可变帧率素材 | `W_VFR` 警告 |
| S13 | 两个同名不同内容的文件，路径含中文、空格、百分号 | 重链接不误配 |
| S14 | 外录音频与主机位双系统同步 | 跨素材对齐 |
| S15 | 中文字幕和英文字幕两条轨，含品牌词和数字 | 字幕文字 |
| S16 | 一个字词跨过剪点 | 字幕截断规则 |
| S17 | 一条独立字幕条，当作标题 | 标题与字幕的区别 |
| S18 | 字幕的序列层例外 | 覆盖值 |
| S19 | 章节标记和待检查标记 | 标记 |

## 6. 验收数字

| 指标 | 通过条件 | 怎么测 | 何时 |
|---|---|---|---|
| 剪点精度 | 支持范围内逐切点零帧偏差，并核对真实源帧 | 读回交换文件比较；宿主渲染后读条码 | 每个导出器 |
| 重链接 | 移盘后按指纹确定性重连；同名文件不误配 | `fixtures:relocate` 后跑 L2 校验 | 第 1 步 |
| 音画同步 | 每个脉冲的起点都落在对应白帧的时间区间内 | 渲染结果检测脉冲和白帧 | 每个导出器 |
| 字幕时间 | 按 `handoff-profile.md` 3.2 节量化；多次剪辑后不漂移 | 对照台词脚本 | 每个导出器 |
| 接手可编辑 | 接手人能移动、修剪片段并保存 | 实机检查单 | 每个导出器 |
| 重复导入 | 第二次导入不把旧时间线当成功 | 实机检查单 | 每个导出器 |
| 导入失败 | 原工程不被破坏，并留下回执 | 故意破坏交换文件 | 第 1 步 |
| Agent 可重现 | 同样的输入得到同样的工程 | 同一请求序列跑两次比较字节 | 第 1 步 |
| 中途失败可回滚 | 写入中途失败，工程保持原样 | 测试里注入失败 | 第 1 步 |
| 幂等 | 同一幂等键重发不重复剪 | 重放请求 | 第 1 步 |
| 不覆盖人的修改 | 旧修订的请求被拒绝 | 冲突测试 | 第 1 步 |
| 撤销粒度 | 一次撤销恰好回到一条指令之前 | 撤销测试 | 第 1 步 |

## 7. 采访评测集

**规模**：10 条团队真实采访素材，合计 30 到 60 分钟。尽量覆盖：

- 干净的普通话单人采访；
- 双人或多人采访；
- 带背景音乐的口播；
- 展会或户外噪声；
- 中文夹英文产品名；
- 数字、单位、品牌词密集的段落；
- 带口音的普通话；
- 一条 30 分钟以上的长段。

**正确稿**：每条素材一份人工校对的文字稿，按句分段，每段给出起止时间。其中 3 条各取 60 秒，人工标注每个词的起止时间，用来测对齐误差。

**清单**：`fixtures/eval/manifest.json` 进仓库，只记录元数据：编号、文件名、大小与指纹、时长、场景标签、语言、说话人数、是否有背景音乐、正确稿的相对路径。素材和正确稿放在本地目录，由环境变量 `ZSIR_EVAL_DIR` 指向，不进仓库。

**指标**：

| 指标 | 用途 |
|---|---|
| 中文字错率、英文词错率、品牌词正确率 | 文字返工频率 |
| 词边界绝对误差的 P50、P95（毫秒） | 剪点和逐词动效能否依赖自动时间 |
| 漏字、重复、无语音误识别次数 | 平均准确率掩盖不了的问题 |
| 每分钟素材的识别耗时、峰值内存、失败率 | 默认模型和机器规格 |
| 每分钟素材的人工校对耗时 | 以整条流程的人工成本选模型 |

默认识别引擎以这套评测集的结果为准，见 ADR-0005。
