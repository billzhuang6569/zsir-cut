# 交接 Profile v0.1

状态：草案 · 2026-10-26 · 依赖 `timeline-schema.md`、`command-protocol.md` v0.1
机器校验：`schema/handoff-manifest.schema.json`、`schema/loss-report.schema.json`
依据：[调研文档](https://claude.ai/artifact/PJytj2A1kDu8Wb4aPSkNdR)「与 DaVinci Resolve / Premiere Pro / Final Cut Pro 联动」一节。

本文定义 `export` 动词交出去的东西：针对哪个软件的哪个版本、交接包里有什么、损失怎么报告、怎样才算交接成功。

## 1. 原则

1. **按目标软件和版本导出，不按格式导出。** 用户选「Final Cut Pro 11」，不选「导出 XML」。一次导出只生成一种交换文件。
2. **一期是单向交接。** 交出去以后，剪辑师在 NLE 里收尾。导回是第二期。
3. **损失在导出之前就说清楚。** 带 `dry_run` 调用 `export` 只返回损失报告，不生成文件。
4. **导出器自己能读回来，不等于目标软件兼容。** 所以验证分四级，最后两级必须在真实软件里做。
5. **同样的输入得到同样的文件。** 同一修订、同一 profile、同一导出器版本，交换文件逐字节相同，这样 CI 才能用 golden 文件比对。

## 2. Profile

profile ID 的格式是「宿主-最低宿主版本-格式-格式版本」。

| Profile | 宿主 | 交换文件 | 字幕 | 一期地位 |
|---|---|---|---|---|
| `fcp-11-fcpxml-1.13` | Final Cut Pro 11 及以上 | FCPXML 1.13 | 内嵌 `<caption>`，另附 SRT | **验收基线** |
| `fcp-10.6-fcpxml-1.11` | Final Cut Pro 10.6 至 10.8 | FCPXML 1.11 | 同上 | 兼容旧版 |
| `resolve-18.5-otio` | DaVinci Resolve 18.5 及以上 | OTIO JSON | SRT 旁路，手动导入字幕轨 | 第二 |
| `premiere-25-xmeml-5` | Premiere Pro 25 及以上 | FCP7 XML（xmeml v5） | SRT 旁路，导入为字幕轨 | 第三 |

选择规则：

- 应用启动时探测本机已安装的宿主和版本，写进用户设置 `~/.zsir-cut/hosts.json`，不写进工程。默认 profile 按探测结果选，用户不需要自己猜版本。
- FCP 会拒绝比自己新的 FCPXML，也会拒绝没通过 DTD 校验的文件。所以 FCP 一律选不高于本机版本的 FCPXML，并用从 FCP 应用包里取出的 DTD 校验。
- Resolve 的默认格式定为 `resolve-18.5-otio`（2026-10-27，Resolve 21.1 实测）。两种格式读回都是逐切点零偏差，但实机导入差别明显：FCPXML 素材在线，可 Resolve 把分层读乱，主画面被放到最上层，若干音频片段被当成画面，片段名丢失，分段变速导入时有告警；OTIO 保留轨道名和分层，素材离线和丢帧起点的问题按 export-otio-xmeml 2.2 修正后解决。`resolve-21-fcpxml-1.11` 保留为备选 profile。
- Premiere 不用 OTIO。它导入 OTIO 后的变速值目前不可信。
- 预留给第二期的：`resolve-21-api`（Studio 版脚本 API 直接建时间线）、`premiere-26-uxp`（自研 UXP 面板）、剪映草稿。

## 3. 交接包

```text
<工程名>_<时间线名>_<profile>_r<修订序号>_<YYYYMMDD-HHMM>/
├─ manifest.json         这次交接的完整说明
├─ loss-report.json      损失报告
├─ 接手说明.txt           给剪辑师看：怎么导入、导入后检查什么
├─ timeline/             交换文件，按 profile 只有一种
├─ subtitles/            每种语言一份 SRT，加一份词级时间 JSON
├─ preview/              参考预览：代理视频，带软字幕轨和时码轨
└─ overlays/             只在需要时出现：带 handles 的透明字幕叠层
```

- 字幕文件：每条字幕轨一份 SRT，文件名 `<语言>.srt`，同一语言有多条轨时加轨道名区分。同一条轨上时间重叠的字幕（例如标题和第一句正文同时出现）不能放进同一份 SRT：按入点顺序贪心分层，第一层写 `<语言>.srt`，放不下的依次写 `<语言>.layer2.srt`、`<语言>.layer3.srt`，接手说明里写明要再导入一条字幕轨。依据：Premiere 25.4 把重叠的两条合并成一条三行字幕。另附 `<语言>.words.json`：一个数组，每条字幕一项，含 `cue_id`、`track_id`、`clip_ids`、`start`、`end`（序列时间，规范有理数，已按 3.2 节量化）、`start_ms`、`end_ms`、`text`、`lines`，以及 `words`（每个可见字词的 `token_id`、`text`、序列时间的 `start`、`end`，不量化）。
- 参考预览在 `render_preview`（任务 1.15）实现后才生成。在那之前交接包不含 `preview/`，清单里也不列。
- 素材不复制，交换文件里写素材的绝对路径。`manifest.json` 记录每个素材的路径、指纹、是否在线、是否用了代理。
- 参考预览给接手人核对画面、声音和字幕节奏，不是成片。格式是 H.264 代理视频加 AAC 音频，封装为 `.mov`：每种字幕语言一条软字幕轨，一条时码轨从时间线起始时码开始。工程名、修订序号、profile 和导出 ID 写进文件元数据和文件名。画面上不烧录任何文字，这样不依赖带文字渲染的 ffmpeg，也能跨平台生成。QuickTime 和常见播放器都能显示软字幕和时码。
- 透明叠层只为目标软件表达不了的元素生成，一个元素一段，不把整条时间线拍平。一期默认不生成，`overlay: true` 时才生成，格式是 ProRes 4444。

### 3.1 稳定 ID 写进交换文件

每个片段的 `clip_id` 和 `occurrence_id` 都写进交换文件，以后导回时靠它们重新匹配：

| 格式 | 写在哪 |
|---|---|
| FCPXML | 片段的 `<metadata>` 里，键名 `com.zsir-cut.clip-id`、`com.zsir-cut.occurrence-id`。如果 FCP 导入时丢弃自定义键，改写进 `note` 属性，第 1 步实测决定 |
| OTIO | 片段的 `metadata["zsir"]` |
| xmeml | 片段的 `<logginginfo>` |

### 3.2 字幕时间量化

字幕在交换文件和 SRT 里都量化到目标时间线的帧网格：入点和出点各取最近的帧边界（正好在两帧中间时取后一帧），量化后不足一帧的延长到一帧，再被所在片段的边界截断。SRT 的毫秒值由量化后的帧时间换算，四舍五入到毫秒。量化只在导出时做，工程文件里的字幕时间不变，所以多次剪辑不会累积漂移。

## 4. 能力矩阵

下表是各 profile 对每项能力的**预期**处理方式，依据是格式规范和调研结论，还没有实机验证。第 1 步每个导出器合并时，用实测结果更新这张表。

状态含义：**保留**指在目标软件里可编辑且一致；**近似**指能用，但外观或结构有变化；**烘焙**指渲染成画面交过去，不能再编辑；**不支持**指丢失，只记录。

| 能力 | FCPXML | OTIO（Resolve） | xmeml（Premiere） |
|---|---|---|---|
| 片段入出点、序列位置、轨道顺序 | 保留 | 保留 | 保留 |
| 序列起始时码、丢帧 | 保留 | 保留 | 保留 |
| 同一次使用的视音频同步、J/L cut | 保留，需按 FCP 主故事情节和连接片段建模，不能把轨道号直接当 lane | 保留 | 保留 |
| 片段启用状态 | 保留 | 保留 | 保留 |
| 恒定增益 | 保留 | 不支持 | 保留 |
| 缩放、旋转、位移、裁切 | 保留 | 不支持 | 保留 |
| 叠化转场 | 保留 | 保留 | 保留 |
| 恒定变速 | 保留 | 保留 | 保留 |
| 分段变速、定格 | 保留 | 近似：按段拆成多个片段 | 近似：按段拆成多个片段 |
| 速度坡度 | 保留 | 近似：按段拆分，坡度变成阶梯 | 近似：同左 |
| 倒放 | 保留 | 保留 | 保留 |
| 标记 | 保留 | 保留 | 保留 |
| 章节层级（`level`） | 近似：章节标记不分级，`feature` 为 `marker_level` | 近似：同左 | 近似：同左 |
| 字幕文字与时间 | 保留 | 近似：文字和时间不变，但需手动导入 SRT | 近似：同左 |
| 字幕样式 | 近似：用字幕默认外观 | 近似 | 近似 |
| 字幕的序列层例外 | 保留，写进文字 | 保留，写进 SRT | 保留，写进 SRT |
| 不认识的 `ext` 数据 | 不支持，只记录 | 写进 metadata | 不支持，只记录 |

一期必须做到的硬指标是表里前四行和字幕文字与时间。其余各项按 profile 逐项实现，做不到的必须出现在损失报告里，不能静默丢掉。

## 5. 损失报告

`loss-report.json` 逐元素列出所有不是「保留」的处理，并按能力汇总保留的数量。`export` 带 `dry_run` 时，信封的 `result` 里就是这份报告。

每条记录的字段：

| 字段 | 说明 |
|---|---|
| `entity_id` / `entity_kind` | 哪个元素 |
| `feature` | 哪项能力，取值见 schema 枚举 |
| `status` | `approximated`、`baked`、`unsupported` |
| `severity` | `info` 外观无变化；`warning` 看起来不同，需在宿主里调整；`error` 内容错误或缺失 |
| `timeline_range` | 影响的序列区间，有理数时间 |
| `reason_code` | 原因编号，见下表 |
| `consequence` | 一句中文，告诉接手人会看到什么、该做什么 |
| `fallback_asset` | 叠层等替代资源在交接包里的路径，没有就是 null |
| `editable_caption_track` | 字幕仍可编辑的位置，例如 FCP 的字幕角色名 |
| `recoverable_from_source_project` | 回到 zsir-cut 工程能否恢复 |

原因编号：

| 编号 | 含义 |
|---|---|
| `R_FORMAT_NO_FIELD` | 交换格式没有对应字段 |
| `R_HOST_IGNORES` | 格式能写，但目标软件导入时会忽略 |
| `R_SPLIT_FOR_RETIME` | 为表达变速把片段拆开了 |
| `R_STYLE_NOT_REPRESENTABLE` | 字幕样式无法在目标软件里表达 |
| `R_SUB_MANUAL_IMPORT` | 字幕需要手动导入 |
| `R_SUB_UNPROJECTED` | 字幕落在倒放段、定格段或静帧上，没有导出。这是按规则有意不显示，内容并没有丢，严重程度为 `warning` |
| `R_BAKED_OVERLAY` | 已渲染成透明叠层 |
| `R_MEDIA_OFFLINE` | 素材离线或指纹不符 |
| `R_EXT_DROPPED` | 扩展数据没有写出 |
| `R_GRID_ROUNDED` | 目标格式要求时间落在某个帧网格上，原值被取整到最近一帧。用于混合帧率下的连接片段 |

报告里只要有 `error` 级的记录，`export` 就返回 `rejected`，错误码 `E_VALIDATION`，除非请求里带 `accept_losses: true`。这样接手人拿到的包，不会有没人看过的严重损失。

## 6. 四级验证

结果都写进 `manifest.json` 的 `validation`，每级记录状态、时间、执行者和说明。

| 级别 | 检查什么 | 谁做 | 一期 |
|---|---|---|---|
| `schema` | 交换文件通过格式校验：FCPXML 过 DTD（只在本机，DTD 不进仓库），OTIO 能被官方库加载，xmeml 过结构检查。再按 6.0 节读回比对，必须零帧偏差 | 导出器自动 | 必须 |
| `media_resolved` | 交换文件引用的每个素材都存在，大小和指纹与工程一致 | 导出器自动 | 必须 |
| `host_import` | 在真实软件里导入，按检查单核对 | Bill 手动，用 `record_handoff_check` 记录 | 每个导出器合并前必须 |
| `host_render_comparison` | 宿主渲染的画面与参考预览逐帧比较。测试素材每帧烧了 asset ID 和源帧号，比较可以自动化 | 一期手动抽查，第 4 步做成自动 | 抽查 |

### 6.0 剪辑表与读回比对

**剪辑表**是比较交接结果的共同格式：时间线上每个视频片段和音频片段一行，字段为：轨道类型（`video` 或 `audio`）、轨道序号（同类轨道里从 1 数起）、`clip_id`、`media_id`、序列入点和出点（帧，按时间线帧率）、源入点和出点（帧，按素材自身帧率；纯音频按 48 kHz 采样；图片按约定的 25 帧）、速度（恒速时的倍数，或「拆段」标记）。所有数值四舍五入为整数，正好在中间时取较大的整数：双系统录音按视频帧对齐后，源入点常落在两个采样之间。按轨道类型、轨道序号、序列入点排序。

- **工程的剪辑表**：直接从工程计算。分段变速在 OTIO 和 xmeml 里会被拆成多个片段，所以按目标格式先把分段变速片段拆开，再算剪辑表。
- **读回的剪辑表**：把导出的交换文件解析回来计算。稳定 ID 写在交换文件的元数据里，用它对应 `clip_id`。
- **零帧偏差**：两张表行数相同，每一行的序列入点、出点、源入点、出点完全相等。损失报告里标为 `unsupported` 的元素不在比较范围内。

### 6.1 实机导入检查单

每次 `host_import` 都核对下面几项，结果逐项记录：

1. 导入没有报错，离线素材数为零。
2. 序列起始时码、总时长、帧率与 `manifest.json` 一致。
3. 每条轨道的片段数一致。
4. 抽三个剪点，看烧录的源帧号与工程一致。
5. J/L cut 处，音频的提前或延后帧数一致。
6. 叠化和变速存在，时长正确。
7. 字幕条数一致，首条和末条的文字与时间一致。
8. 保存、关闭、重新打开后以上不变。

## 8. 直接导出

直接导出不交给剪辑软件，只往 `output` 文件夹里写文件（ADR-0015）。不生成 manifest、交接包目录和损失报告；`export` 的结果信封列出写出的文件和大小。`dry_run` 时只返回将要写的文件名。文件名用「时间线名_修订序号」，例如 `主时间线_r8.srt`，已存在时不覆盖，返回 `rejected`、`E_VALIDATION`。

| Profile | 写出 | 规则 |
|---|---|---|
| `direct-srt` | 每条启用的字幕轨一份 `.srt` | 与交接包里的 SRT 完全相同：同样的投影、时间量化（3.2 节）和重叠分层。多条字幕轨时文件名加轨道名 |
| `direct-audio-wav` | 一个 `.wav` | 见下文 |

**音频混音（`direct-audio-wav`）**：

- 范围是整条时间线，从序列 0 到总长。
- 参与的是所有启用的音频轨上所有启用的音频片段。每个片段按自己的源区间、时间映射（变速按 `timeline-schema.md` 4.5，一期只做 `linear` 和 `hold`）和 `gain_db` 取样，按序列位置叠加。各轨增益都是 0 dB，不做自动音量平衡。
- 声道：输出立体声。单声道的源（或 `source_channels` 只取一个声道的片段）两边各放一份，不衰减；立体声的源左右对应；多于两个声道的源只取前两个，结果信封加 `W_AUDIO_CHANNELS_DROPPED`。
- 格式：48 kHz、24 位 PCM、小端。
- 叠加后超过满刻度的采样直接截断，结果信封加 `W_AUDIO_CLIPPED` 并写出截断的采样数。不加限幅器，免得悄悄改变声音。
- 叠化转场按两段等功率交叉淡化。
- 素材离线返回 `failed`、`E_IO`，不写半个文件。
- 验收：用 `fixtures.md` 的脉冲测试素材导出，每个脉冲的起点落在对应白帧的时间区间内；同一工程导出两次字节相同。

成片（MP4，可选烧进字幕）放二期；它会复用第 9 节的字幕渲染器。

## 9. 字幕叠层

产品说明见 `product.md` 5.1，决定见 ADR-0017。字幕叠层是只含字幕的透明视频，用户放在剪辑软件时间线的最上层；改字幕后再导出，写回同一个文件。

### 9.1 导出

`export` 的 `profile` 取 `subtitle-overlay`，参数 `overlay_id`（`subtitle_overlays[]` 里的一项），不需要 `output`。

| 项 | 规则 |
|---|---|
| 尺寸 | 与时间线的 `format` 相同（全画布） |
| 帧率 | 时间线的 `edit_rate`；丢帧时间线照写丢帧时码 |
| 时长 | 从序列时间 0 到时间线总长加 `tail`，按帧向上取整 |
| 起始时码 | 时间线的 `start_timecode`，写进文件的时码轨，拖进剪辑软件后能按时码对齐 |
| 编码 | ProRes 4444，带透明通道（ffmpeg `prores_ks`，`profile 4444`，像素格式 `yuva444p10le`），封装 `.mov`，没有音频 |
| 内容 | 字幕轨按投影规则（`timeline-schema.md` 5.2）得到的每条字幕，时间按第 3.2 节量化到帧；没有字幕的帧完全透明 |
| 样式 | 每条字幕用自己的 `style_id`，没有就用字幕轨的默认样式，按 9.2 节渲染 |

写入方式：先写到同目录的临时文件（`.<文件名>.zcut-tmp`），编码完成并校验能读出帧数后，原子替换 `output_path`。中途失败，原文件不变。成功后在同一个写入里更新这个叠层的 `last_export`（修订 ID、UTC 时间、字节数），所以导出会产生一个新修订。`export` 是长任务，返回 `accepted` 和任务 ID。

结果信封列出文件路径、帧数、字幕条数。字体找不到时用回退字体继续导出，`result.warnings` 加 `W_FONT_FALLBACK` 并写出缺的字体名。

### 9.2 渲染器

字幕叠层和桌面版「字幕 › 样式」面板的预览用同一套排版代码，保证看到什么就导出什么。

- 排版代码是一个独立的 TypeScript 模块，只依赖标准的 Canvas 2D 接口（`CanvasRenderingContext2D`）：给它一条字幕的文字、样式、画布尺寸，它在画布上画出这条字幕。
- 桌面版预览用浏览器自带的 Canvas。导出时在 Node 里用 `@napi-rs/canvas`（MIT，Skia）提供同样的接口。两边的排版位置、换行、字号、底板尺寸完全一致；只允许字体抗锯齿的像素级差别。
- 换行：先按字幕条的 `breaks`；一行仍超过 `max_width` 时，在字与字之间自动折行，最多 `max_lines` 行，超出的部分照画但给 `W_SUB_OVERFLOW`。
- 描边画在文字外侧，底板是包住所有行的一个圆角矩形，`padding` 和 `radius` 都按字号换算成像素。
- 一条字幕渲染成一张透明 PNG（整幅画布大小），相同文字和样式的字幕只渲染一次。然后按每条字幕的帧区间排成一个序列交给 ffmpeg 编码：用 concat 列表，每张图片写明持续的帧数，字幕之间的空隙用一张全透明图片。不需要 ffmpeg 带 libass。

### 9.3 验证

- 自动：用标准工程导出，读回文件：尺寸、帧率、帧数、时码、编码和像素格式都对；在每条字幕的中间帧，字幕区域有不透明像素；在两条字幕之间的帧，整帧透明。同一修订导出两次，解码后的每一帧逐像素相同。
- 覆盖：导出一次，改一条字幕的文字，再导出，文件路径不变、修订和 `last_export` 更新，改过的那条在对应帧上变了，其他帧不变。
- 实机（Bill）：在 FCP、Premiere、Resolve、剪映里各拖一次，确认透明通道正常、位置铺满、时码对齐；覆盖导出后各软件能否自动更新画面，记进第 7 节的宿主版本表旁边。
