# 字幕断句规则 v0.1

状态：草案 · 2026-10-26 · 依赖 `timeline-schema.md` 第 5 节
依据：[调研文档](https://claude.ai/artifact/PJytj2A1kDu8Wb4aPSkNdR)「断句与 LLM 后处理」一节。

本文定义如何把母稿里的字词切成字幕条，以及每条字幕的换行和显示时间。`transcribe` 生成初始字幕条和 `resegment` 重新断句都用这套规则。规则是确定的：同样的字词和同样的规则配置，只有一种结果。语义层面的合并拆分由 LLM 在这之后作为编辑命令提出，不属于本文。

## 1. 规则配置

| 参数 | `zh-talk` | `en-talk` | 说明 |
|---|---|---|---|
| `cpl` | 16 | 42 | 每行宽度上限 |
| `max_lines` | 2 | 2 | 每条最多行数，样式里有 `max_lines` 时取较小值 |
| `cps` | 9 | 20 | 每秒字数上限，超过只警告 |
| `min_duration` | 1.0 s | 1.0 s | |
| `max_duration` | 6.0 s | 6.0 s | |
| `hard_pause` | 0.7 s | 0.7 s | 字词间停顿达到这个值必须分条 |
| `soft_pause` | 0.3 s | 0.3 s | 优先分条的停顿 |
| `min_gap` | 0.08 s | 0.08 s | 相邻两条之间至少空出的时间 |
| `strip_end_punct` | true | false | 显示时去掉每行末尾的标点 |

默认按母稿语言选：`zh*` 用 `zh-talk`，其余用 `en-talk`。`resegment` 请求的 `rules` 可以给一个配置名，再覆盖其中几项；带 `rules` 的 `resegment` 把它保存到母稿的 `subtitle_rules` 字段。之后的断句、显示时间计算和校验都按母稿的 `subtitle_rules`，没有这个字段时用语言默认配置。

## 2. 宽度

- `zh-talk`：中日韩文字和全角标点每个算 1，其余字符每个算 0.5。
- `en-talk`：中日韩文字和全角标点每个算 2，其余字符每个算 1。
- 一条字幕的宽度是它显示出来的全部字词宽度之和，字词之间的空格按配置规则计入：中文字词之间不加空格；英文字词之间加一个空格。中英混排时，相邻两个字词交界处的两个字符都是 ASCII 字母或数字，就在中间加一个空格，例如「every cut」，但「Agent先把」不加。空格的宽度按本节规则计算。
- 只计 `text` 非空的字词。

## 3. 标点

句末标点：`。！？.!?`。句内标点：`，、；：,;:`。

标点如果是单独的字词，就并入前一个字词处理，不能成为一行或一条的开头。

## 4. 分句

按字词顺序扫描，遇到以下任一情况就在这个字词之后分句：

1. 字词以句末标点结尾。
2. 这个字词的 `end` 到下一个字词的 `start` 之间的停顿 ≥ `hard_pause`。

`state` 为 `approved` 的字词所在的字幕条，以及 `locked` 的字幕条，不参与重新断句，它们把扫描范围切成几段，每段单独处理。

## 5. 句内分条

对每个句子，从第一个字词开始贪心地往当前字幕条里加字词。加入下一个字词会让当前条超过下面任一上限时，就要分条：

- 宽度超过 `cpl × max_lines`；
- 时长（第一个字词的 `start` 到最后一个字词的 `end`）超过 `max_duration`。

分条位置不一定在当前字词。在当前条已有的字词边界里，只看宽度已过当前条一半之后的那些，按下面的优先级挑一个，同一优先级取最靠后的：

1. 边界处停顿 ≥ `soft_pause`；
2. 边界前一个字词以句内标点结尾；
3. 当前条的最后一个字词之后。

分出的前半部分成为一条，后半部分作为新一条的开头，继续扫描。

单个字词本身就超过宽度上限时，它独占一条，并给出警告 `W_SUB_TOO_WIDE`。

## 6. 换行

一条字幕的宽度不超过 `cpl` 时只有一行。超过时分成两行，换行点在字词边界上，规则如下：

1. 候选位置是所有能让两行都不超过 `cpl` 的字词边界。
2. 在候选里优先选前一个字词以句内标点结尾的边界。
3. 同一优先级里，选两行宽度差最小的；还相同就选靠前的。

换行点记录在字幕条的 `breaks` 里。英文按字词边界换行，所以不会在单词中间断开。

## 7. 显示时间

1. 起点是第一个字词的 `align.start`，终点是最后一个字词的 `align.end`。
2. 时长不足 `min_duration` 时，把终点往后延，但不超过下一条的起点减 `min_gap`。延不够就保留延到的位置，并给出警告 `W_SUB_SHORT`。
3. 显示宽度除以时长大于 `cps` 时，用同样的方式往后延，延不够就给出警告 `W_SUB_CPS`。
4. 与下一条的间隔小于 `min_gap` 时，把本条终点提前到下一条起点减 `min_gap`。

这里算出的是源时间，不写进 `cues[].timing`。`timing` 只存人工覆盖值，有覆盖值时以覆盖值为准，不再做本节的调整。投影时，本节算出的起点和终点替代首字词的起点和末字词的终点，再按 `timeline-schema.md` 5.2 节换算到序列，见第 3 步。导出时按交接 profile 第 3.2 节量化到帧。

本节的「下一条」指同一母稿里按源时间排在后面的那一条字幕条。

## 8. 例子

字词时间单位为秒，配置为 `zh-talk`。

**例一：一行一条。** 一条（0.00–0.44）、三（0.44–0.66）、分钟（0.66–1.10）、的（1.10–1.32）、采访（1.32–1.76）、大概（1.76–2.20）、要（2.20–2.42）、剪（2.42–2.64）、两（2.64–2.86）、小时（2.86–3.30）。宽度 15，不超过 16，一行。时长 3.30 s，每秒 4.5 字，不触发任何调整。结果：一条，0.00–3.30，无换行。

**例二：两行一条。** 字词依次是「剪辑师」「拿到」「的」「工程」「还能」「继续」「改，」「这」「才」「叫」「真正」「的」「交接」，中间没有达到 0.3 s 的停顿。总宽度 22，超过 16 但不超过 32，所以一条两行。能让两行都不超过 16 的边界里，「改，」之后的边界前一个字词以句内标点结尾，优先选它。第一行是「剪辑师拿到的工程还能继续改，」，宽 14；第二行是「这才叫真正的交接」，宽 8。显示时 `strip_end_punct` 去掉第一行末尾的逗号。

**例三：分条。** 一个句子的字词总宽度 40，超过 32。加到第一个让宽度超过 32 的字词时分条。在已有字词宽度超过 16 之后的边界里，若有停顿 ≥ 0.3 s 的边界，就在其中最靠后的一个分开；没有就看句内标点；都没有就在当前最后一个字词之后分开。

## 9. 新增校验规则

以下三条加入 `timeline-schema.md` 第 8 节，由 `validate` 对按本文算出的显示结果检查：

| 编号 | 级别 | 规则 |
|---|---|---|
| `W_SUB_TOO_WIDE` | 警告 | 单个字词宽度超过一行上限 |
| `W_SUB_SHORT` | 警告 | 字幕显示时长不足 `min_duration` 且无法延长；或者投影到序列后，因剪辑截断或变速，显示时长不足 `min_duration`。后者 `ids` 写字幕轨、字幕条和片段 |
| `W_SUB_CPS` | 警告 | 每秒字数超过 `cps` 且无法延长 |
