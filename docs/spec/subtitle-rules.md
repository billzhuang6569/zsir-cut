# 字幕断句规则 v0.1

状态：草案 · 2026-10-26 · 依赖 `timeline-schema.md` 第 5 节
依据：[调研文档](https://claude.ai/artifact/PJytj2A1kDu8Wb4aPSkNdR)「断句与 LLM 后处理」一节。

本文定义如何把母稿里的字词切成字幕条，以及每条字幕的换行和显示时间。字幕的断点由 AI 按意思决定（第 10、11 节，ADR-0021）；第 4、5 节的规则断句只用于 `transcribe` 生成初始字幕条，以及没有可用 AI 时的退路。规则是确定的：同样的字词和同样的规则配置，只有一种结果。

## 1. 规则配置

| 参数 | `zh-talk` | `en-talk` | 说明 |
|---|---|---|---|
| `cpl` | 16 | 42 | 每行宽度上限 |
| `max_lines` | 1 | 2 | 每条最多行数，样式里有 `max_lines` 时取较小值 |
| `cps` | 9 | 20 | 每秒字数上限，超过只警告 |
| `min_duration` | 1.0 s | 1.0 s | |
| `max_duration` | 6.0 s | 6.0 s | |
| `hard_pause` | 0.7 s | 0.7 s | 字词间停顿达到这个值必须分条 |
| `soft_pause` | 0.3 s | 0.3 s | 优先分条的停顿 |
| `min_gap` | 0.08 s | 0.08 s | 相邻两条之间至少空出的时间 |
| `strip_end_punct` | true | false | 显示时去掉每行末尾的标点 |

`zh-talk` 的 `max_lines` 原为 2，2026-10-30 改为 1：Bill 走查时一条两行、最多 32 个字的字幕在短视频里太长。已经存了 `subtitle_rules` 的母稿不受影响。

默认按母稿语言选：`zh*` 用 `zh-talk`，其余用 `en-talk`。`resegment` 请求的 `rules` 可以给一个配置名，再覆盖其中几项；带 `rules` 的 `resegment` 把它保存到母稿的 `subtitle_rules` 字段。之后的断句、显示时间计算和校验都按母稿的 `subtitle_rules`，没有这个字段时用语言默认配置。

## 2. 宽度

- `zh-talk`：中日韩文字和全角标点每个算 1，其余字符每个算 0.5。
- `en-talk`：中日韩文字和全角标点每个算 2，其余字符每个算 1。
- 一条字幕的宽度是它显示出来的全部字词宽度之和，字词之间的空格按配置规则计入：中文字词之间不加空格；英文字词之间加一个空格。中英混排时，相邻两个字词交界处的两个字符都是 ASCII 字母或数字，就在中间加一个空格，例如「every cut」，但「Agent先把」不加。空格的宽度按本节规则计算。
- 只计 `text` 非空的字词。

## 3. 标点

句末标点：`。！？.!?`。句内标点：`，、；：,;:`。

标点如果是单独的字词，就并入前一个字词处理，不能成为一行或一条的开头。

## 4. 分句

按字词顺序扫描，遇到以下任一情况就在这个字词之后分句：

1. 字词以句末标点结尾。
2. 这个字词的 `end` 到下一个字词的 `start` 之间的停顿 ≥ `hard_pause`。

`state` 为 `approved` 的字词所在的字幕条，以及 `locked` 的字幕条，不参与重新断句，它们把扫描范围切成几段，每段单独处理。

## 5. 句内分条

对每个句子，从第一个字词开始贪心地往当前字幕条里加字词。加入下一个字词会让当前条超过下面任一上限时，就要分条：

- 宽度超过 `cpl × max_lines`；
- 时长（第一个字词的 `start` 到最后一个字词的 `end`）超过 `max_duration`。

分条位置不一定在当前字词。在当前条已有的字词边界里，只看宽度已过当前条一半之后的那些，按下面的优先级挑一个，同一优先级取最靠后的：

1. 边界处停顿 ≥ `soft_pause`；
2. 边界前一个字词以句内标点结尾；
3. 当前条的最后一个字词之后。

候选是宽度已过当前条一半之后的所有字词边界，不只是当前条的最后一个字词之后；第 3 级指其中不满足第 1、2 级的普通边界，同一优先级取最靠后的。

但「坏边界」排在以上所有候选之后：只有没有别的候选时才用，坏边界之间仍按上面的优先级挑。坏边界指以下任一种（字词的 `text` 去掉首尾标点后整体比较，不做子串匹配）：

- 前一个字词在「不断后」表里：的、地、得、和、与、跟、及、或、在、是、把、被、给、对、向、从、往、让、将、很、最、更、太、都、也、还、就、又、才、再、而、并、这、那、这个、那个、这些、那些、一个、一些、一种、一位、每、各、第；
- 后一个字词在「不断前」表里：的、地、得、了、着、过、吗、呢、吧、啊、呀、嘛、啦、们、上、下、里、中、后、前、时、似的、一样。

另外两种边界也算坏边界：

- 拆开名词：工程 `recognition.terms` 里的某个名词，在边界两侧显示文字拼起来时跨过这个边界（名词的一部分在前一条、一部分在后一条）。英文名词不分大小写。
- 拆开数字：前一个字词显示文字的最后一个字符是数字（`0-9`，或「零一二三四五六七八九十百千万亿两几半」之一），并且后一个字词的第一个字符是数字或量词单位（「个位家条年月日天号点分秒岁元块倍次小时%」之一）。

两张表和这两条都只用于 `zh-talk`。第 4 节的分句（句末标点、`hard_pause`）不受坏边界影响。

分出的前半部分成为一条，后半部分作为新一条的开头，继续扫描。

单个字词本身就超过宽度上限时，它独占一条，并给出警告 `W_SUB_TOO_WIDE`。

## 6. 换行

一条字幕的宽度不超过 `cpl` 时只有一行。超过时分成两行，换行点在字词边界上，规则如下：

1. 候选位置是所有能让两行都不超过 `cpl` 的字词边界。
2. 在候选里优先选前一个字词以句内标点结尾的边界。
3. 同一优先级里，选两行宽度差最小的；还相同就选靠前的。

换行点记录在字幕条的 `breaks` 里。英文按字词边界换行，所以不会在单词中间断开。

## 7. 显示时间

1. 起点是第一个显示的字词（`text` 非空）的 `align.start`，终点是最后一个显示的字词的 `align.end`。被隐藏的字词不参与起止，但第 2 到 4 步照常做：含隐藏字词的字幕条同样按 `min_duration`、`cps` 延长，按 `min_gap` 让开下一条。
2. 时长不足 `min_duration` 时，把终点往后延，但不超过下一条的起点减 `min_gap`。延不够就保留延到的位置，并给出警告 `W_SUB_SHORT`。
3. 显示宽度除以时长大于 `cps` 时，用同样的方式往后延，延不够就给出警告 `W_SUB_CPS`。
4. 与下一条的间隔小于 `min_gap` 时，把本条终点提前到下一条起点减 `min_gap`。

这里算出的是源时间，不写进 `cues[].timing`。`timing` 只存人工覆盖值，有覆盖值时以覆盖值为准，不再做本节的调整。投影时，本节算出的起点和终点替代首字词的起点和末字词的终点，再按 `timeline-schema.md` 5.2 节换算到序列，见第 3 步。导出时按交接 profile 第 3.2 节量化到帧。

本节的「下一条」指同一母稿里按源时间排在后面的那一条字幕条。

## 8. 例子

字词时间单位为秒，配置为 `zh-talk`。

**例一：一行一条。** 一条（0.00–0.44）、三（0.44–0.66）、分钟（0.66–1.10）、的（1.10–1.32）、采访（1.32–1.76）、大概（1.76–2.20）、要（2.20–2.42）、剪（2.42–2.64）、两（2.64–2.86）、小时（2.86–3.30）。宽度 15，不超过 16，一行。时长 3.30 s，每秒 4.5 字，不触发任何调整。结果：一条，0.00–3.30，无换行。

**例二：两行一条。** 字词依次是「剪辑师」「拿到」「的」「工程」「还能」「继续」「改，」「这」「才」「叫」「真正」「的」「交接」，中间没有达到 0.3 s 的停顿。总宽度 22，超过 16 但不超过 32，所以一条两行。能让两行都不超过 16 的边界里，「改，」之后的边界前一个字词以句内标点结尾，优先选它。第一行是「剪辑师拿到的工程还能继续改，」，宽 14；第二行是「这才叫真正的交接」，宽 8。显示时 `strip_end_punct` 去掉第一行末尾的逗号。

**例三：分条。** 一个句子的字词总宽度 40，超过 32。加到第一个让宽度超过 32 的字词时分条。在已有字词宽度超过 16 之后的边界里，若有停顿 ≥ 0.3 s 的边界，就在其中最靠后的一个分开；没有就看句内标点；都没有就在当前最后一个字词之后分开。

## 9. 新增校验规则

以下三条加入 `timeline-schema.md` 第 8 节，由 `validate` 对按本文算出的显示结果检查：

| 编号 | 级别 | 规则 |
|---|---|---|
| `W_SUB_TOO_WIDE` | 警告 | 单个字词宽度超过一行上限；或者带 AI 断点的字幕条宽度超过 `cpl × max_lines`、时长超过 `max_duration` |
| `W_SUB_SHORT` | 警告 | 字幕显示时长不足 `min_duration` 且无法延长；或者投影到序列后，因剪辑截断或变速，显示时长不足 `min_duration`。后者 `ids` 写字幕轨、字幕条和片段 |
| `W_SUB_CPS` | 警告 | 每秒字数超过 `cps` 且无法延长 |

## 10. AI 断点

`resegment` 可以带 `cut_after`：字词 ID 数组，表示在这些字词之后断开（`edit-ops.md`）。断点全部由 AI 决定（ADR-0021），带了 `cut_after` 时，范围内的分条改为：

1. 只在 `cut_after` 里的字词之后断开，以及范围的末尾。第 4 节的分句（句末标点、`hard_pause`）和第 5 节的句内分条都不用。`cut_after` 不在范围内、或指向隐藏字词的项忽略。
2. 内核不移动、不增删断点。一段宽度超过 `cpl × max_lines` 或时长超过 `max_duration` 时仍是一条，宽度超过 `cpl` 时按第 6 节换成两行（`max_lines` 为 1 也换）；两行都放不下时，在让第一行不超过 `cpl` 的最靠后的字词边界换行，`validate` 给警告 `W_SUB_TOO_WIDE`。
3. 不合并：AI 给的两段再短也各是一条，短的照第 7 节延长、给警告。
4. 锁定和已批准的字幕条照常跳过，它们的边界总是断开。

`resegment` 不带 `range` 且带 `cut_after` 时，内核在母稿的 `ext["zsir.subtitle_pass"]` 写 `{ "by": <author.name> }`，表示整份母稿已经过 AI 整理。`transcribe` 重新生成字幕条，或不带 `cut_after` 的 `resegment` 覆盖整份母稿时，删掉这个标记。带 `range` 的 `resegment` 不写标记；`range` 恰好覆盖整份母稿的规则重分段同样删除标记。

## 11. 字幕整理（桌面版自动做）

宿主进程在以下两种情况自动整理一份母稿，不需要用户操作：

- 这份母稿的 `transcribe` 任务成功完成，不论是界面发起还是 AI 面板里的 Agent 发起；
- 打开工程时，有母稿已有字幕条但没有 `ext["zsir.subtitle_pass"]` 标记。

### 11.1 做法

1. **分块**：母稿的显示字词（`text` 非空、不在锁定或已批准的字幕条里）按顺序切块，每块不超过 600 个字词。只在必须切时切：剩下的字词超过 600 个，就在前 600 个字词里停顿最长的边界处切（相同取靠后的）。块的边界一定断开，锁定和已批准的字幕条也把字词切成不同的块。最多 6 块同时处理。
2. **调用 Agent**：用 AI 面板当前选的 Agent（没选就用检测到的第一个，Claude Code 优先），无头运行、不给任何工具和 MCP，只进文字出 JSON。Claude Code 和 Codex 都用它们自己的默认模型（2026-10-31 实测 sonnet 断句质量明显低于默认模型）。每次调用超时 120 秒。
3. **输入**（每块）：提示词（11.2）加一段 JSON：`{"text": "…", "remove_fillers": true, "terms": ["豆包",…], "max_chars": 16}`。`text` 是本块字词按顺序拼起来的文字，字词之间的停顿 ≥ `soft_pause` 处插入「 / 」，停顿 ≥ `hard_pause` 处插入「 // 」，其余不加分隔（英文字词之间加一个空格）。`max_chars` 是 `cpl × max_lines`。
4. **输出**：`{"lines": ["…", …]}`，按顺序的每条字幕文字。
5. **对齐**：宿主把 `lines` 和本块字词对齐。比较前，行里的空白、「/」和第 3 节的标点全部去掉，字词文字同样去掉空白和标点。按顺序，每行必须正好由连续若干字词的文字拼成，中间允许跳过整个字词；行与行之间也允许跳过整个字词；最后一行之后剩下的字词也算跳过。跳过的字词就是要隐藏的字词。对齐有多种方式时取跳过最少的；还相同时，重复出现的字词跳过靠前的那个。对不上（改了字、加了字、顺序变了、拆开了一个字词）按输出不合法。
6. **隐藏的限制**：`remove_fillers` 为 false 时不允许跳过字词；跳过的字词超过本块 20%，或包含 `terms` 里的名词，按输出不合法。
7. **检查与修改**：对齐成功后，宿主逐行检查下面几项，问题写成中文短句，例如「第 12 行『然后豆包呢它会每天』结尾是没说完的『每天』」：
   - 宽度超过 `max_chars`，或时长超过 `max_duration`；
   - 结尾或开头落在第 5 节的坏边界上，包括拆开名词和数字。「不断后」表里的「的、地、得」不算；边界处停顿 ≥ `soft_pause` 的不算（说话人确实停了）。
   有问题时，把原输入、上一次的 `lines` 和问题列表一起发给 Agent（11.2 最后一段），要求它只改有问题的行及其相邻行，仍输出完整的 `lines`。最多两轮修改。修改的输出不合法，就用上一次合法的结果。两轮后仍有的问题保留，不由程序改动。
8. **失败重试**：调用失败、超时或输出不合法时，重新调用一次（不算修改轮）。
9. **写入**：所有块完成后，一次 `edit` 批次提交：先 `hide_tokens`（跳过的字词），再一个不带 `range`、带全部断点的 `resegment`，断点是每一行最后一个字词。`author` 为 `{kind: "agent", name: "字幕整理"}`，`label` 为「AI 整理字幕」，在历史面板里是一步，能撤销。修订冲突时基于新修订重跑一次整个整理。
10. **退路**：没有可用 Agent，或某块重试后仍失败，这块用规则断句（这块的断点按第 4、5 节计算后作为 `cut_after` 给出），其余块照用 AI 结果；结果信封和界面给警告 `W_SUB_PASS_FALLBACK`，写明原因。全部块都失败时不写 `ext["zsir.subtitle_pass"]`，下次打开工程再试。

### 11.2 给 Agent 的提示词

提示词写进宿主代码，内容与 Skill `references/subtitles.md`「断句」一节一致，改的时候两处一起改。它必须包含：

- 任务：把一段没有标点的口语转写切成短视频字幕，每行一条，只切不改字；
- 输入里「/」「//」的意思（短停顿、长停顿），以及停顿只是参考，断点按意思定；
- 断句要求和正反例子（见 Skill）；
- 去除水词的要求（`remove_fillers` 为 true 时）：去掉的字直接不写；
- 输出格式：只输出 JSON `{"lines": [...]}`，不加解释；
- 修改轮的说明：给出上一次的 `lines` 和问题列表，只改有问题的行及其相邻行，其余行原样保留，仍输出完整的 `lines`。

### 11.3 界面

- 整理进行中：字幕面板顶部状态显示「AI 整理字幕…」和进度（已完成块数 / 总块数），列表区域不显示字幕条，改为一行说明「识别完成，AI 正在按意思断句，大约还要 N 分钟」（N 按每块 60 秒、6 块并发估计，向上取整，至少 1）。时间线上这份母稿的字幕片段照常占位，但不显示文字；预览不叠这份母稿的字幕。
- 完成后：恢复「已识别 · 第 N 版 · M 条字幕」，显示 AI 的结果。退回规则断句时状态旁显示一个提示图标，悬停说明原因。
- 不加按钮。
