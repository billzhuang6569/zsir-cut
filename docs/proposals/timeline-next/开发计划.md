## 剪辑师应该能完成什么

剪辑师把采访从 Finder 拖进空时间线，画面和同期声一起出现。选一段，说「删掉这段里的重复开头，关于预算那句先留着」。AI 直接剪，字幕跟着人声走。剪辑师可以一边回放一边拖剪点。若两次表述分别是「三十万」和「十三万」，右上角才出现一张卡，带原话、位置和两个选项。剪辑师可以先去剪下一段，再回来回答。

版本以「从空工程到交给专业剪辑软件」为边界。优先交付媒体落轨、调整剪点、AI 主线编辑、局部提问和撤销。调色、特效、完整 FCP 连接故事线、多机位同步、第三套完整快捷键预设留到后续。采访用来验收，所有交互同样适用于活动记录、产品片、录屏和纯音频项目。

## 时间线交互合同草案

| 剪辑师的动作 | 松手前应看到 | 松手后的结果 |
|---|---|---|
| 从系统拖一个或多个文件到空时间线 | 整个空轨道是落区。提示将放在哪条轨、文件顺序和导入进度。 | 导入后从第 0 帧依序排布。多选按可确定的拖入顺序，平台未提供顺序时显示并采用文件名自然排序。单次撤销移除这次落轨，已导入素材留在素材库。 |
| 从素材库或源监视器放入 I/O 选区 | 以所选源范围画等长虚影，显示目标帧、V/A 目标轨和模式。键盘也能完成「插入／覆盖／追加到片尾」。 | 有声画面默认落到配对的视频、音频轨，共用 occurrence。纯音频上音轨，图片默认 5 秒。用户可显式选仅声音或仅画面。错误轨道提示原因。 |
| 在已有剪点插入，或放到一段中间 | 插入画让位线和受波及的后续轨，覆盖高亮被替换区间。开着磁性时默认插入，关闭时默认覆盖；当前模式可点选。 | 插入沿用 core 全轨合拢和字幕投影；覆盖只改已选目标轨，保留覆盖区外的片段和其他轨。空隙按落点放置。显式「追加」按实际片尾放置。 |
| 移动现有片段、修剪或滚动剪点 | 保留抓取偏移；组选和联动片段一起出现虚影。显示吸附线、边缘变化帧数和到素材头尾的提示。靠近视口边缘自动滚动。 | 同轨或兼容轨移动保留现有 insert/place 规则。自由移动撞到占用区给出原因；已有片段覆盖式移动单独排期。滚动剪点保总时长，波纹按实际影响轨预览。 |
| 精调与反悔 | 选中片段、剪点、播放头三者视觉可分。鼠标命中边缘、切割或滚动时指针对应当前工具。 | 保留切割、逐帧、留空删除、波纹删除、撤销/重做。取消手势用 Esc，按住拖动期间不写工程。每次落点一次提交。历史回看和草稿预览明确显示只读。 |

**两个经常出错的边界。** 把空镜盖在采访上，应选上方视频轨和「仅画面」，保留下方采访原声。把带同期声的采访拖到主轨，松手前应能看到 V1 和 A1 两块虚影。两种落法都能在工具栏完成，快捷键依据当前面板焦点，尤其要避免素材入轨的 Q 和 Premiere 修剪的 Q 同时执行。

**外部文件的两阶段写入。** 宿主接系统文件、识别逻辑像素和滚动偏移，同一次拖动只接收一次。先用现有 import_media 完成指纹识别，再以新媒体 ID 执行一次原子 edit。导入失败的文件逐个说明，多选有失败时保留成功导入的素材并等用户选择是否放其余文件。拖入期间切换工程即取消原落点。导入时人手改变目标片段，就重新解析锚点并显示变化；无法定位便保留素材供重新放置。重试复用导入结果，禁止重复排片。缺少兼容轨时，以同一 edit 建轨并放置，整次放置可一起撤销。

## Agent 直接剪的产品规则

| 情景 | 应有行为 | 用户在界面上看到什么 |
|---|---|---|
| 明确要求执行，范围、对象和结果可确定 | 如「删掉选区里第二遍相同的介绍」或「把这段空镜接到结尾」，直接编辑主工程，用一个语义完整的 edit 提交。 | 时间线即时更新；历史写明删了哪段、为什么、短了多久。点记录看剪点或撤销。 |
| 同一任务里某处缺证据，其他段互相独立 | 先做能确定的全部。存疑处保留现状，用片段身份、源范围和当前修订挂一条问题。有依赖的编辑等这条回答。 | 右上角显示「待你决定 · 1」。没有问题时只给简短完成回执。 |
| 目标本身无法确定 | 比如工程里有两条成片，用户说「把那条剪短」且未选中。先问能解开范围的一件事。 | 当场给两条时间线的名称供选。选完即继续。 |
| 用户问「怎么剪」或明确要先看方案 | 咨询只读。明确要试方案时走现有 manual 草稿，再审阅、批准或放弃。旧工程的未结草稿继续走原路径。 | 面板清楚区分「正在看方案」与「当前时间线」，预览内容与写入目标一致。 |
| 涉及保护内容、费用或工程外副作用 | 锁定字幕保留。需要强制改动时走现有手审批准规则。导出、云端识别、付费配音及全局库操作仍按宿主已有许可处理。 | 「请求许可」单列，写明作用与已有许可范围；剪辑判断的计数单独计算。 |

**右上角的最小卡片。** 以「客户预算录了两遍，保留哪句？」为题，显示 A「三十万」和 B「十三万」两段源时码、各自试听、为什么推荐、选择后的影响。可选择、补充或稍后处理。回答一条即按最新修订重新定位并处理该条。跳过保持当前剪辑。问题独立于聊天，换 Agent、关闭再开仍能找回。另设折叠的「本轮已剪」列表，读历史回执，支持定位、回放剪点和撤销。正在生成时也可以查看或回答，答复按任务串行消费。

**协议缺口与推荐解法。** 现有决定挂在 session.json，上层只看活动会话；自动批准的会话会关闭，未答问题随之只读。简单把 manual 改成 auto 无法实现上表。建议给直接模式增加工程级待决事项，放工程旁的 .zcut 元数据，由 core 统一读写。沿用现有问题、选项、推荐、引用和回答结构；新增的主线作用域、来源修订、稳定源锚点、答后执行回执及读写入口，须由 Claude 定合同、Bill 批准。旧 session 决定照旧读，不搬移或补批历史草稿。打开旧工程时缺少新元数据就视作空队列。规格正式命名前，此提案不指定新动词或错误码。

**回答与执行是两件事。** 人的回答先持久化；改动成功后单独关联工程回执。断线重开从未完成的回答继续，同一回答重复投递只写一次。内容改过但目标仍可证实时重算时间；用户或 Agent 已删掉目标便显示「这一段已经改过」并让人重新定位或关闭。修改先前回答须先核对已生效修订。用户答「保留」应记录决定，可不产生剪辑修订。审阅旧草稿、保护字幕和宿主许可都不能由模型冒充用户批准。

## MCP 与提示词怎样落地

1. **先读上下文。** 桌面读 ui_state 的选区、播放头和当前面板，再用 inspect(brief/timeline) 读当前时间线及修订。无头入口从显式工程、时间线和范围开始。对「这段」优先用选中实体，指代不清才问。转写按需读选区和前后一句；重复使用同源素材时带具体 clip_id。
2. **让工具能被正确选中。** 给已有工具加用途、主线/草稿写入位置、必要参数、成功或排队后的下一步。把「从素材选句搭线」「删选区内重复」「比较两种说法」「仅校字幕」做成共享短例子。工具列表保留兼容；桌面只经 MCP，无头 CLI 和 MCP 调用相同 core。把桌面需要的粗剪指南打包注入或按需提供，禁用 shell 的客户端也能读到。
3. **同一意图只写一次。** 简单动作一个 edit，带 label、reason、author.kind=agent、base_revision 和幂等键；同一请求包含多项 ops 时原子生效。独立段落可以分次提交。多步才使用短批次；已有批次执行期间会占用同一目标，不能持锁等人回答。停止时展示已生效和未执行部分，可撤销已做批次。
4. **从工程验证。** 读 receipt、changes、verification；对比前后时长、目标片段、保留原话和字幕投影。视觉判断按需用已有剪点胶片或局部回放。MCP 若只给文件路径，给受限桌面 Agent 定义可读剪点证据的返回方式；无法读到画面时只报告结构自查。修订冲突先重读取证再重算请求。committed_unverified 先查回执，未知结果禁止盲重放。
5. **分开工作流与授权。** 共享规则描述「执行、咨询、试方案」和锁定边界，各入口只补传输规则。改正手审示例的修订来源，清除桌面流程中写本地剪辑说明、自动再跑字幕整理、必须交整案的冲突指引；在真 Claude Code 与 Codex 上分别回归。

**拟注入的核心指令样例**

> 用户要求剪辑且对象明确时，先读取当前工程和选区，把已确定的改动直接写到主时间线。保留用户指定的原话和自然停顿。出现两个合理剪法且会改变含义时，只挂起涉及的片段，给出原话和可试听位置；继续处理独立部分。用户只问建议时只读，明确要求先看方案时才建手审草稿。写后根据回执和剪辑表汇报实际结果。不要把字幕文字校对变成删除原声。

**用于验收的调用轨迹。** 指令「删掉选区的重复开头，保留后面的解释」。桌面 ui_state → inspect(brief) → inspect(timeline, range) → read_transcript(timeline_id, range) → edit（不带 session_id，以 remove_span 的 tokens 和 clip_id 锚定重复句）→ inspect(timeline, range) 与 read_transcript 回读 → 返回「已剪」和历史定位。若另有两句数字冲突，再记录一条独立问题；本轮清晰部分已经落在主线。无范围或保护内容时按上表分流。

**范围收缩顺序。** 进度紧时先延后双画面修剪、复杂多选反馈和更多键位。两条拖放路径、音画同步、直接编辑、回答一条就能继续、撤销与旧工程兼容构成最小可发布版本。若主线决定或并发保护未过，小范围试用沿用手审入口；不要把尚不能恢复的自动写入默认为所有人打开。回退编辑偏好时仍须能读到已产生的历史和问题。

## 怎样判断这一版值得发布

下表是目标，不是当前实测值。第一周留同机录像、系统与素材清单。界面速度在同一台 Apple Silicon Mac、同一缓存状态、同一工程上量两版；另用 Windows x64 安装包查输入与缩放差异。人工观察以实际任务成功为主。

| 验收场景 | 放行标准 |
|---|---|
| 首次放素材 | 3 位分别熟悉 FCP、PR、Resolve 的剪辑师，在空工程无指导拖入带声视频，并能独立做一次插入和一次覆盖。记录失败路径，P0 体验问题解决后重测。 |
| 拖放与剪点 | Finder/资源管理器、素材卡、源 I/O、空轨、已占轨、音频、图片、混合多选、取消、离线或无权限文件均有结果。25 和 30000/1001 帧率、非零起始时码、缩放与水平滚动下，预览与实际落点差 0 帧。 |
| 8 个高频动作 | 放入、选择、移动、切割、普通修剪、滚动剪点、删除合拢、撤销/重做逐项验。带声素材不丢同期声，显式仅画面保留底层声音；波纹后的字幕、标记和 AV 保持同步。 |
| 交互速度 | 提议基准工程 30 分钟、200 段、4 轨；采样至少 20 次拖动。拖动反馈 p95 ≤ 33 ms；本地已入库落轨松手至 UI 回显 p95 ≤ 200 ms，系统导入计时另列。缓存冷启动单列。 |
