# ADR-0027 桌面版 AI 直接剪进时间线，只问拿不准的事

状态：已采纳 · 2026-11-18 · 修改 ADR-0014（「决定」挂在编辑会话上）

## 背景

ADR-0014 和 `command-protocol.md` 第 7 节定的流程是：Agent 开一个 `manual` 编辑会话，在草稿里剪完，交审，人「全部批准」后才进主工程。桌面版宿主每轮都给 Agent 写死「使用 manual 编辑会话，交出草稿用 session_review，不能自行批准」（`packages/app-host/src/agents.ts` 第 208 行）；Skill 的粗剪说明还要求「开始前确认这几件事，用户没说的就问，一次问完」。

Bill 2026-11-18 的反馈：现在 AI 剪完要整个方案问用户，太重。希望 AI 决定以后直接操作时间线，只有拿不准的才问。

实际用下来的问题：

1. 说一句「把这句删了」，也要开会话、交审、批准、合并，人要多点三次。
2. 审方案时人只能整体批准或拒绝，不能只要其中一部分。
3. 开工前先问一串问题，用户没法先看到东西再说。
4. 决定只能挂在会话上，不开会话就不能问。

撤销和历史已经很完整：每次写入都是一个步骤，能撤销，能回到任意一步，历史只增不删（`product.md` 6.1）。在这个底子上，直接写主工程的风险是可控的。

## 决策

1. **默认直接剪。** 桌面版里 Agent 不开编辑会话，直接对主工程发 `edit`，每一步必须带 `label`（做了什么）和 `reason`（为什么）。改动马上出现在时间线上。
2. **一轮对话是一组。** 宿主给一轮对话里的全部写入打上同一个 `turn` 标记。历史面板按轮折叠；右栏「AI 动态」列出这一轮改了什么，可以「撤回这一轮」（回到这一轮开始前的修订，本身也是一个新步骤），也可以逐步点开看。
3. **先做后问。** AI 拿不准时，先按它认为最好的做法做，再留一条决定：「我先按 A 做了，要换成 B 吗？」。选项可以带上准备好的操作，用户点了直接执行，不用再等 AI 回一轮。先做的那一版必须是最保守、能一键换掉的：涉及意思和事实（数字、否定、人名）时，最保守就是不删、保留原样。同一轮里和这条无关的部分照常做完，依赖它的等回答。
4. **什么才算拿不准**，写进提示词，只有下面几类才问，每轮最多 3 条：
   - 会改变说话人意思或事实的剪辑（否定句、数字、人名）；
   - 两种做法都说得通且影响大（结构顺序、整段去留）；
   - 用户没给、AI 也推断不出的目标（例如目标时长），而且影响整轮工作。
   其他的（口误、重复、停顿、剪点位置）AI 自己定，在汇报里说明。
5. **决定不再必须挂在会话上。** 决定可以直接挂在工程上（新增存放位置和动词，规格另写）；会话里的决定照旧。
6. **编辑会话保留，变成可选。** 用户要「给我两版看看」或者明确要求先出方案时才用会话和审方案。CLI 和 Skill 的命令行用法不变。
7. **人批准过的仍然不能被自动改。** `approved` 的字词、`locked` 的字幕条照旧返回 `E_LOCKED`。

## 后果

- 规格：`command-protocol.md` 加工程级决定、选项带操作、`turn` 标记和「撤回一轮」；`desktop-host.md` 第 4.4 节换掉写死的会话指令；`product.md` 第 4 节改写。
- 界面：右栏「决定」改为「AI 动态」：本轮改动、待你决定、许可卡三块；时间线上标出 AI 这一轮改过的片段。
- 人和 AI 可能同时改主工程：靠现有的 `base_revision` 冲突检测，Agent 收到 `conflict` 重新读再做。AI 正在剪时时间线上显示提示，不锁人。
- 设置里留「AI 剪辑方式」开关（直接剪 / 先出方案让我审）。工程级决定或并发保护没过验收前，默认先出方案。
- 验收方式变了：不再看「方案能不能批准」，看「AI 一轮做对了多少、问了几次、撤回了几次」，用 Agent 评测集衡量。

## 考虑过的其他方案

- **保留会话，加「部分批准」。** 每一步都要人点，仍然是「全盘问」，只是颗粒更细。不采用。
- **会话用 `approval: auto`。** 能省掉批准，但改动仍先落在草稿里，时间线要等交审才变，撤销也只能整个会话一起撤。不采用。
- **按置信度分数自动决定问不问。** 模型自己报的分数不可靠，改用上面写明的几类情况。
