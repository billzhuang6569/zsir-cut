# ADR-0019 语音：用 fish.audio 克隆音色和生成配音

状态：已采纳 · 2026-10-30

## 背景

Bill 想在庄Sir剪辑里直接做 AI 配音：用自己或采访对象的声音克隆音色，念旁白，或者给选中的字幕配音，然后拖上时间线。这是第一层需求，排在剪辑软件插件之前。

## 决策

- 服务商用 fish.audio：克隆只要一段 10 到 30 秒的参考音频，建好立即可用；中文效果好；按字节计费，没有月费。默认模型 `s2.1-pro`。
- 音色库放在本机，所有工程共用，和名词库同一目录。音色实际存在 fish.audio，本机记它的 ID 和一段试听音频。
- API Key 只存 macOS 钥匙串，不进文件和 git。
- 生成的音频作为普通素材进工程，信息写在素材的 `ext["zsir.voice"]` 里。这样拖放、导出、交接都不用另做。
- 字幕配音记住对应的字幕，拖上时间线时给推荐位置；字幕改了标出过期。推荐位置和过期都现算，不存进工程。
- 选了多条字幕时，每条一段还是合成一段，由用户在生成弹窗里选（Bill 2026-10-30）。
- 语音面板分「克隆 · 生成 · 结果」三个子页（Bill 2026-10-30）。

规格见 `docs/spec/voice.md`。

## 后果

- 第一次有功能要联网和花钱。测试一律用假的客户端，CI 不联网。
- 新增本机文件 `settings.json`、`voices.json` 和 `voices/` 目录；新增钥匙串条目。
- 删除音色会同时删掉 fish.audio 上的模型，界面要二次确认。
- 工程里的配音素材在另一台机器上照常可用，但音色库不跟着走。

## 考虑过的其他方案

- 本地开源 TTS 模型：不花钱，但要带几 GB 的模型和 GPU 依赖，克隆效果不稳，先不做。
- 每次生成都直接上传参考音频（零样本克隆，不建模型）：不用管理远端模型，但每次请求都要传音频，慢，fish.audio 也建议先建模型。
