# ADR-0014 桌面版内置对话面板，驱动本机 Agent；「决定」写进工程

状态：已采纳 · 2026-10-29

## 背景

Bill 在界面设计里给功能区加了 AI 标签：一个对话窗口，模仿 Open Design，调用用户本机的 Agent 命令行。AI 剪完后要把待决事项交给人选，选完自动接着做。调研文档的原则是外部 Agent 自由接入、「不绑一套私有聊天上下文」、「工程数据是权威，聊天记录不是」。

## 决策

- 对话面板只是外壳：它启动并驱动用户本机安装的 Agent 命令行（先支持 Claude Code 和 Codex），把它的输出渲染成界面。软件不带自己的模型，不保存私有的聊天上下文。
- AI 交给人拍板的事叫「决定」。决定挂在编辑会话上，存进工程：问题、选项、推荐项、关联的时间点或对象、状态、人的回答。
- 回答决定有两条路，效果相同：在界面上点选（同时往对话里发一条消息），或者由 Agent 通过 MCP 写入回答。
- 没答完的决定不阻止批准，但批准前要提示。

## 后果

- `command-protocol.md` 要加决定的数据结构和读写动词，`timeline-schema.md` 要加它在工程里的位置。在第 3 步的规格修订里做。
- 换一个 Agent 或换一台电脑，打开工程就能看到还有哪些事没定。
- 对话面板要处理本机没装 Agent、未登录、命令行版本不兼容等情况，在 `design.md` 里写状态。

## 考虑过的其他方案

- 决定只存在对话里：实现简单，但换 Agent 就丢，违背「工程数据是权威」。
- 软件内置模型：要管 API key、计费和模型更新，也把用户绑在一家模型上。
