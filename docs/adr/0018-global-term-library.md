# ADR-0018 全局名词库：工程里出现两次的专有名词自动收录

状态：已采纳 · 2026-10-30

## 背景

Bill 走查时发现识别设置里一个专有名词都没有。原因是当时只从 `reference_text` 里抽名词，他没贴参考文本；Agent 也没把识别出的「豆包」写进工程，而是直接塞给了热词参数。同一个团队反复拍同一批客户和产品，名词每个工程都要重新教一遍。

## 决策

- Agent 识别完后从文稿里抽专有名词，写进工程的 `recognition.terms`。
- 本机建一份全局名词库。工程名词在本工程文稿里出现 2 次及以上，自动收进名词库；之后所有工程识别时都把名词库当热词。
- 收录门槛由内核按字词数次数，结果确定；「什么算专有名词」由 Agent 判断。
- 用户可以手动加、删、屏蔽。管理界面放在以后的设置页，现在先有动词和 CLI。

规格见 `docs/spec/term-library.md`。

## 后果

- 识别结果依赖本机名词库，同一工程在两台机器上的热词可能不同。实际用的热词表写进运行记录，可以追查。
- 名词库变了会让同一素材重新识别，缓存命中率下降。

## 考虑过的其他方案

- 新工程创建时把名词库拷进 `recognition.terms`：结果完全由工程决定，但每个工程的名词列表会被上百个无关的词塞满，面板里没法看。
- 按「出现在 2 个以上工程」收录：更稳，但第一个工程里反复出现的词要等到第二个工程才生效，Bill 的说法是出现两次就收。
