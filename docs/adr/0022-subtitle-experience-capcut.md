# ADR-0022 字幕体验对标剪映

状态：已采纳 · 2026-10-31 · 修改 ADR-0021 第 4 条的界面部分

## 背景

Bill 2026-10-31 要求字幕的分行、界面交互、编辑操作、样式编辑全面对标剪映，并且 App 里几乎所有操作都能让 Agent 调用。调查结论见 `.tmp/answers/字幕调查.html`（不进 git），要点：

- App 里的 Agent 现在只能自己读字幕、自己切，再用 `resegment` 提交。慢，不经过宿主的检查和修改轮，Skill 还写着「桌面版里不用你做」。
- 剪映是闭源软件，只能照它的交互做。开源里没有能整体搬来的字幕编辑器。可以改写移植的：slate-transcript-editor（MIT，回车拆行、退格合并时分配字词时间）、OpenReel（MIT，逐字动画、多选和查找替换）、OpenCut 旧版（MIT，吸附和拖边、描边和底板绘制）。
- 卡卡字幕助手（VideoCaptioner，GPL-3.0）只借鉴做法：分行后单独跑一遍 AI 校对，用改动比例拦住乱改；先让 AI 读全片写概要和名词，再交给后面几步。

## 决策

1. **交互照剪映，外观用我们的设计系统。** 快捷键、操作顺序、面板分区和剪映一致，颜色、图标、间距用 `design/` 里的变量。
2. **整理和校对是 Agent 能调用的动词。** 新增两个桌面版动词 `subtitle_tidy`（按意思重新分行）和 `subtitle_proofread`（校对错字），走宿主的整理流程：分块并发、宿主检查、退回修改。Agent 和界面调用同一个入口。它们需要宿主进程调 Agent，所以和界面动词一样只在桌面版提供，CLI 没有。
3. **识别后的自动流程变成三步：概要、分行、校对。** 概要和名词只读不写字幕；分行照 ADR-0021；校对只改错字，每行改动超过限度就退回 AI，最终仍超限的那一处不改。校对失败不影响分行结果。
4. **字幕列表像剪映一样编辑。** 点字直接在行里改，回车在光标处拆成两条，行首退格并到上一条，多选后批量操作。光标落在一个字词中间时，先用新操作 `split_token` 把字词拆开再拆条，两步在一个批次里，撤销一次全部回去。
5. **样式加深，动画进渲染器。** 样式加多层描边、阴影、发光、斜体、下划线、字间距、对齐、逐字高亮色和动画。预览、样式面板、字幕叠层仍用同一个渲染器（`handoff-profile.md` 9.2）。动画只在字幕叠层和预览里有，交给剪辑软件的字幕按 `R_STYLE_NOT_REPRESENTABLE` 记进损失报告。
6. **预设样式内置在 App 里。** 套用预设就是把它的字段写进工程里的样式（`update_style`），工程文件不引用预设。

## 后果

- `subtitle-rules.md` 11.3 的「不加重新断句按钮」作废：字幕面板选中若干条后可以让 AI 重新整理，可带一句要求。
- 时间线上的字幕片段能拖两端改显示时间（写 `set_cue` 的 `timing`），不能整条拖动：字幕跟着说话走，要挪就挪说话的片段。
- 校对会把字词改成 `edited`，`heard` 保留原来听到的，所以随时能看 AI 改了哪些字。
- 渲染器要知道当前时间和每个字词的时间才能画动画，叠层导出从「一条字幕一张图」改为「画面变化时才多出一张图」。

## 考虑过的其他方案

- **换成 libass 渲染。** 不采用。浏览器预览要用 JASSUB，它打包了 LGPL 组件，不在 AGENTS.md 允许的许可里；而且换了以后要维护两套渲染。
- **整体移植 OpenReel 的字幕模块。** 不采用。它的列表没有回车拆行，导出和预览看起来走了两套绘制，时间全是浮点。只改写它的动画部分。
- **校对交给 Agent 在对话里做。** 不采用，理由和 ADR-0021 一样：慢，也没有程序检查。
