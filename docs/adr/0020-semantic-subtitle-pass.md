# ADR-0020 字幕按意思断句：识别后自动跑一轮 AI 整理

状态：已采纳 · 2026-10-30

## 背景

识别出来的字词没有标点，字幕只能按停顿和字数切。Bill 走查自己的采访工程：一条字幕结尾落在「是你」，「抖音」被切到两条，「呃」「啊」和「上传上传」这样的口头重复都留着。他的要求是：做出来的字幕就是做好的，不要用户再点按钮重排。

断句要懂意思，内核本身没有语言模型。

## 决策

- 识别完成后自动跑一轮「字幕整理」：AI 读文稿，决定在哪些字词后面断开，以及（开了去除水词时）隐藏哪些口头禅和重复。内核按这些断点重排字幕条。
- AI 只给断点和要隐藏的字词，不改字、不改时间。每行宽度、最长时长、和声音对齐仍由规则保证：AI 的一段超过上限，内核在段内按规则再切。
- 桌面版由宿主进程自动做，用用户已经装好的 Claude Code 或 Codex，无工具、只进文字出 JSON。整理写成一步编辑，在历史里看得到、能撤销。不加按钮。
- 命令行和 MCP 场景由调用方 Agent 按 Skill 自己做同样的事，用同一个编辑操作。
- 规则断句同时改进：不在「的、和、在、是」这类字后面断，不在「了、吗、呢、上」这类字前面断，除非没有别的位置。AI 不可用时，字幕仍比以前好。

规格见 `docs/spec/subtitle-rules.md` 第 5、10、11 节，`docs/spec/edit-ops.md` 的 `resegment`。

## 后果

- 识别完到字幕可用多了一段等待（1 小时采访约 1 到 2 分钟）。界面显示「整理字幕」。
- 结果不再只由字词和规则决定，而是由 AI 给的断点决定；断点作为编辑请求写进日志，重放仍得到同样的字节。
- 用到用户本机的 Agent 额度。没有可用 Agent 时退回规则断句并提示。

## 考虑过的其他方案

- 在字幕面板放「AI 重新断句」按钮：Bill 否决，字幕应该一出来就是好的。
- 让 AI 一条条调 `split_cue` / `merge_cues`：1 小时采访几百条，太慢也容易出错。
- 本地分词模型（jieba 一类）只解决词边界，不懂意群，做不到「一条一个完整意思」。
