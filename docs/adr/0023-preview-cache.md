# ADR-0023 预览缓存：按片段生成代理段，播放时接成一条流

状态：已采纳 · 2026-11-06 · 补充 P2.1（两个播放器轮流播）

## 背景

桌面版的预览用一个 `<video>` 直接放原素材，剪点处要 seek 到下一段的入点，Bill 2026-11-04 实测仍然卡顿。P2.1 改成两个播放器轮流播（下一段提前 0.3 秒开始准备），Claude 在合成素材上量到剪点处最大帧间隔仍有 366 到 400 毫秒：seek 本身就要这么久，提前量只能藏住一部分。

Final Cut Pro 和 Premiere 的做法是先把时间线渲染成代理或缓存，播放时读缓存，不临时解码原素材。Bill 问能不能照这个做，并要求缓存位置能在设置里改（F3）。

Claude 2026-11-06 用 Playwright WebKit（和 Tauri 的 WKWebView 同一个引擎）做了初测：把 5 个片段各编成一段 fMP4（`h264_videotoolbox`，30 帧每秒、关键帧间隔 15 帧，`-movflags +frag_keyframe+empty_moov+default_base_moof`），用 Media Source Extensions 的 `sequence` 模式按顺序喂进一个 `SourceBuffer`，连续播 5 段：`seeking` 0 次、`waiting` 0 次、最大帧间隔 67 毫秒（正常帧间隔 33 毫秒）；一段 3 秒的片段 0.3 秒就能编出来。

## 决策

1. **每个视频片段一段缓存，不整条渲染。** 键是 `hash(素材指纹 + 源入点 + 源出点 + 速度 + 画质)`，所以挪片段、改字幕、改别的片段都不重做；`trim` 只重做被改的那一段。整条时间线渲染成一个文件的做法不采用：剪一刀全部重做。
2. **格式是 fMP4。** 视频 H.264，默认 720p（短边 720，保持比例），关键帧间隔 0.5 秒；声音 AAC 48 kHz 单声道。macOS 上用 `h264_videotoolbox`，没有 VideoToolbox 时退回 `libx264 -preset veryfast`。文件不写时间戳，同样的输入两次生成逐字节相同。
3. **播放时用 MSE 接成一条流。** 上层只有一个 `<video>`，`SourceBuffer` 用 `sequence` 模式按时间线顺序追加各段，剪点处不 seek。播放头、字幕叠层、时码仍按现有办法从时间线推算，不靠 `<video>` 的 `currentTime` 反推片段。
4. **没备好的段退回 P2.1。** 某段状态是 `building` 或 `missing` 时，那个剪点用两个播放器轮流播原素材；段备好后下一次经过剪点时再接上。缓存目录不存在（外接盘拔了）时全部按 `missing`，播放不中断，只是回到 P2.1 的水平。
5. **缓存是宿主的事，不是内核的。** 生成队列、状态推送、清理、设置都在 `packages/app-host`，规格见 `desktop-host.md` 第 5 节。内核的 `render_preview` 不变，仍给 Agent 用。
6. **导出永远用原素材。** 缓存只给预览，不进交接包，不进工程文件。
7. **默认位置和上限。** `~/Movies/庄Sir剪辑助手/预览缓存`，上限 20 GB，画质 720p；设置里能改位置、上限、画质，能整个清空或按工程清空（Bill 2026-11-06 定）。

## 后果

- **复测（2026-11-06，Claude）**：Bill 的采访素材（1920×1080、30 帧、H.264），按测试工程的真实剪辑表取 6 段（0.56 到 10.12 秒），按本文第 2 条编码：每段 0.24 到 0.5 秒编好。Playwright WebKit 里用 MSE 连播三次：`seeking` 0 次；剪点处帧间隔多数 66 到 68 毫秒（2 帧），最大一次 95 毫秒；现在的做法剪点处停 366 到 400 毫秒。另有两次在**开始播放**时卡 0.77 秒、`waiting` 1 次，不在剪点上：要先把播放头所在段和下一段追加进缓冲再开始播放。结论：可以派 U3.9 和 U3.17。WKWebView 里的实测放在 U3.17 验收时做（真 App 才有它）。
- 第一次打开工程要等缓存生成；队列按播放头附近优先，所以用户先看的地方先好。
- 宿主多一条后台编码线：用电池时可以暂停（设置项），不和导出、识别抢 CPU 的策略一期不做。
- `tools/acceptance/preview_seam.mjs` 要能识别 MSE 模式并统计 `waiting` 次数和 `SourceBuffer` 的间隙。

## 考虑过的其他方案

- **只做 P2.1 的两个播放器。** 已做，剪点处仍停 366 到 400 毫秒，是 seek 的硬成本。
- **整条时间线渲染成一个代理文件。** 任何改动都要全部重做，一小时的采访要等几分钟。
- **WebCodecs 自己解码、自己画到 canvas。** 控制最细，但要自己做音画同步和音频输出，WKWebView 对 WebCodecs 的支持也不完整。
- **用原素材直接喂 MSE。** 原素材的关键帧间隔通常 1 到 10 秒，按片段入点切不开，必须重编码。
