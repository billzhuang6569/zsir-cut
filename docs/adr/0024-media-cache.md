# ADR-0024 素材缓存：波形和缩略图按素材一次生成，存进缓存目录

状态：已采纳 · 2026-11-07

## 背景

Bill 2026-11-07 在 Mac 开发版上看到：时间线上每个片段只有第一格缩略图，后面是灰的，要等很久才陆续出来；他要求「借鉴 FCP 的缓存创建机制，把波形、缩略图都存缓存里」。

当时的做法：界面每画一格缩略图就请求一次 `/thumb?at=<精确时间>`，宿主为每个请求起一个 ffmpeg 抽一帧，同时最多 2 个；缩放、滚动一变，精确时间就变，又是一批新的 ffmpeg。波形 `/peaks` 按素材一次算，存成 JSON。两者都存在各工程旁边的 `.zcut/<project_id>/cache/`，不计入预览缓存的上限，设置里清不掉，换个工程用同一个素材要重做一遍。

Final Cut Pro 的做法：素材导入资源库后，后台任务马上为每个素材生成波形数据（Peaks）和缩略图（Thumbnail Media），存在资源库的缓存里，按素材而不是按时间线存；时间线只读这些文件，缩放时不重新解码。生成的文件可以在「删除生成的资源库文件」里一起清掉。

## 决策

1. **按素材生成，不按片段、不按请求。** 键是素材指纹（`timeline-schema.md` 的 `fingerprint`），同一个素材在几个片段、几个工程里只做一份。
2. **导入和打开时在后台先做好。** 和预览段共用后台队列，排在预览段前面；当前时间线用到的素材先做。界面不再为每一格缩略图起 ffmpeg。
3. **缩略图存成固定间隔的拼图。** 按素材时长取 1、2 或 5 秒一张，每张高 96 像素，100 张拼成一个 JPEG，另有一个索引文件。界面按最接近的时间取格子；只有放大到比间隔还细时才按需抽单帧，抽出来的也存下。
4. **波形存成二进制峰值。** 每秒 100 个值、每个 1 字节，一小时的素材约 360 KB，整条取一次，缩放在界面里算。
5. **和预览段放在同一个缓存目录。** `<缓存目录>/media/<素材键>/`，计入上限、能在设置里看到和清空；超上限时先删预览段，再删素材缓存。缓存目录不可用（外接盘拔了）时退回旧的 `.zcut/` 位置和按需生成，界面不出错。
6. **素材文件只读。** 生成只读取素材，不写回、不移动（AGENTS.md 硬规则 5）。

细节（文件格式、队列、通道路径、推送字段、清理顺序）见 `desktop-host.md` 第 6.5 节。

## 后果

- 打开一个新工程，时间线先用主色铺底、波形画细中线，几秒内换成真缩略图和波形；第二次打开立刻就有。
- 宿主多一类缓存文件和一组通道路径；旧的 `/thumb`、`/peaks` 保留一个版本后删除。
- 旧 `.zcut/<project_id>/cache/` 里的文件不再新增，宿主不迁移也不删除，用户可以手动删。
- 拼图的缩略图在最细的缩放上不是逐帧准确的，要靠按需单帧补；这和 FCP 放大后才逐帧补齐的表现一致。

## 考虑过的其他方案

- **保留按请求抽帧，只加大并发。** 每次缩放都要重新抽，素材越长越慢，CPU 占满时还和预览段编码抢。
- **每张缩略图一个文件。** 一小时的素材按 2 秒一张是 1800 个小文件，目录和请求都太多；拼图把它压到 18 个文件。
- **把缩略图和波形放进工程文件或 `.zcut/`。** 换工程要重做，清不掉，也不计入上限；工程文件也会变大，违背「工程文件只放剪辑决定」。
