# 0.2 版开发计划：剪辑手感、AI 直接剪、Agent 接口

状态：草案 · 2026-11-18 · 里程碑「0.2 剪辑手感与 AI 直接剪」
来源：Bill 2026-11-18：时间线编辑太粗糙（例如不能拖入素材）；Agent 控制剪辑线的 MCP 和提示词要优化；AI 剪完应该直接改时间线，只有拿不准的才问，不要全盘方案都问。要求站在产品经理视角整体优化，可以借鉴 OpenCut 等开源时间线。
相关决策：ADR-0027（AI 直接剪，修改 ADR-0014）。0.1.0 的发布（`release-0.1.md` 的 R2）照常进行，本计划的规格和设计工作可以并行。

## 1. 现状：看到了什么

### 1.1 时间线

已有：点选、⌘ 多选、框选；同轨和跨轨移动（视音频一起）；拖边缘修剪（磁性时连带后移）、滚动编辑、剪点选中和逐帧微调；切割工具（落在鼠标帧、Shift 切所有轨、Option 只切一段）；删除和删除并合拢；吸附；缩放；J/K/L；浏览条；撤销重做；从素材面板把素材拖到某条轨上（覆盖方式放置）。两套快捷键（FCP、Premiere）38 个动作。

缺的和有问题的（审计依据见文末附录）：

| 类别 | 问题 |
|---|---|
| 拖入 | Finder 里的文件拖到时间线上没有反应，只能先拖进素材面板；拖进轨道之间或最下面不会新建轨道；拖动中没有片段的影子，看不出会放多长、落在哪条轨；只能覆盖，不能插入 |
| 三点编辑 | 时间线上「设入点 I」按钮没有接功能；入出点只当播放范围用，不能「删掉入出点之间」；没有插入 `,`、覆盖 `.`、追加 `E`、FCP 的连接 `Q`；素材面板的 `Q` 不看修饰键，可能和时间线的 `Q`（修剪到播放头）同时触发 |
| 移动 | 移动到会重叠的位置、多片段跨轨移动，界面不预先判断，松手后才被内核拒绝，用户看不到原因；没有覆盖式拖动 |
| 剪贴板 | 没有复制、剪切、粘贴、复制一份（⌥ 拖） |
| 轨道 | 轨道头只有一个图标：不能新建、改名、删除、锁定、静音、独奏、隐藏，也不能单独调高度 |
| 片段 | 没有右键菜单；没有属性面板，音量、启用、变速、位置大小、名字都改不了（内核 `set_clip` 早就有） |
| 修剪 | 没有 slip、slide；`[` `]` `\` 选剪点边、`⇧,` `⇧.` 移 10 帧没做；变速片段不能修剪 |
| 空隙 | 不能选中空隙，没有「删除空隙」「合拢全部空隙」 |
| 标记 | 复查标记只能点了跳过去，不能改、不能删 |
| 预览 | 只播最上面一条视频轨；声音只用每个片段自带的音轨，单独的声音轨、J/L cut 听不到；不显示位置大小 |
| 性能 | 每个片段都是一个 DOM 节点，没有只画看得见的部分，长工程会卡 |
| 其他 | ⌘K 命令面板按钮没有功能 |

### 1.2 AI 怎么剪

- **每次都要整体批准。** 宿主每轮都写死「使用 manual 编辑会话，交出草稿用 session_review，不能自行批准」（`app-host/src/agents.ts:208`）。说一句「删掉这句」也要开会话、交审、批准。
- **开工先问一串。** Skill 粗剪说明第 1 节要求「用户没说的就问，一次问完」。
- **桌面版拿到的是命令行版说明。** 宿主把 `skills/zsir-cut/SKILL.md` 整份接进系统提示，里面教的是 `zcut` 命令行和在 `zcut-agent/requests/` 写请求文件；而桌面指令又禁止命令行和写文件。两套说法互相打架，粗剪、字幕等 `references/` 也没带上。
- **MCP 工具没有说明。** 31 个内核工具加 6 个界面工具，只有名字和参数 schema，没有一句 `description`（`packages/mcp/src/index.ts`、`app-host/src/index.ts:202`）。`edit` 一个工具装下 30 多种操作，schema 很大，Agent 只能靠猜。
- **结果只放在结构化字段里。** 工具返回 `content: []`，只填 `structuredContent`；不认结构化结果的客户端什么也看不到，认的也要读完整信封。
- **AI 不知道用户在看哪。** 每轮不带播放头、选中的片段、入出点，用户说「把这段删了」，AI 要自己调 `ui_state` 才知道「这段」是哪段，经常不调。
- **操作太底层。** 「删掉所有口误」「把停顿压到 0.3 秒」「只留这三段」都要 Agent 自己拼一长串 `remove_span`、`place`，容易错，也慢。
- **决定只能挂在会话上。** 不开会话就不能问。

### 1.3 可以借鉴的

| 来源 | 借什么 | 许可 |
|---|---|---|
| OpenCut（opencut-classic，`apps/web/src/timeline/controllers/drag-drop-controller.ts`） | 拖放先算出「落点」：第几条轨、是不是新轨、时间；拖到轨道之间就新建轨道；Finder 文件先导入再按同一个落点放置；所有改动走命令对象，批量命令一次撤销；剪贴板、复制一份、书签都是命令 | MIT，可参考写法 |
| Pireel（`packages/studio-engine/src/agent-*`、`review-brief.ts`、`timeline-audit.ts`） | Agent 通过 MCP 操作时间线；工具按任务分层；给 Agent 的「审阅简报」和时间线自检 | AGPL，**只借思路，不看实现细节，不抄代码** |
| Cursor 一类编程 Agent | 直接改、可以逐块看和撤回；改动高亮 | 产品模式 |
| Descript、剪映 | 按文字剪：删字就是删画面；一键去口误、去停顿 | 产品模式 |
| FCP、Premiere、Resolve | 三点编辑、源监视器补丁、轨道头、右键菜单、slip/slide、拖放修饰键 | 交互习惯 |

没有找到叫 openchatcut 的开源项目；ChatCut 是商业产品，开源的只有给它用的 Skill。

## 2. 目标：0.2 版做成什么样

1. **时间线：** 剪辑师不看说明，凭 FCP 或 Premiere 的习惯就能完成常用剪辑：拖入、三点编辑、复制粘贴、轨道控制、右键、属性、slip/slide。
2. **AI：** 说一句话，时间线马上变；一轮结束右边列出改了什么，可以整轮撤回；只有拿不准的才问，而且问的时候已经先做了一版。
3. **Agent 接口：** 任何 Agent 读工具说明就知道怎么用；常见任务一个操作完成；AI 知道用户正看着哪里。

验收用三个数字：

| 指标 | 目标 |
|---|---|
| 时间线常用操作对照表（附录 B，40 项） | 全部能做，Bill 实机试手感通过 |
| Agent 评测集（第 6 节）一次做对率 | ≥ 85%（不需要用户追问就达成要求） |
| 每轮问用户的条数 | 中位数 0，最多 3 |

## 6. 验收

**Claude**（每个 PR）：在 WebKit 里用测试工程的隔离副本，逐项走附录 B 对照表；内核操作有单元测试和 golden；导出不变的工程三家导出字节不变。

**Agent 评测集**（新建 `tools/acceptance/agent-evals/`，Claude 维护）：20 条指令，每条一个起始工程和检查规则，Claude Code 和 Codex 各跑一遍：

| 类别 | 例子 | 检查 |
|---|---|---|
| 指代 | 选中一段后说「把这段删了」 | 只删选中的；没开会话；问了 0 次 |
| 去口误 | 「把口误和重复的起头都去掉」 | 用了 `remove_fillers` 或等价操作；没删掉有意义的字 |
| 定长 | 「剪成 60 秒」 | 结果 54–66 秒；整句进出 |
| 拿不准 | 素材里有「不是 A，是 B」且超时长 | 先做一版，留 1 条决定，选项带操作 |
| 撤回 | 「刚才那轮不要了」 | 用撤回一轮，主工程回到那轮之前 |

失败的写成新的评测条目。

**Bill**：T1–T5 合并后试一次时间线手感；A1、A2 合并后用一段真实素材让 AI 剪一遍，看效果和问的问题是否合适；最后在 FCP 里导入一次确认交接没退步。
