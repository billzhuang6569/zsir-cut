# 打磨第 2 轮：剪点处播放不卡

来源：Bill 2026-11-04 实机试用字幕第 4 轮后说「在接缝处播放的时候还是会卡顿，别的都正常」。

共同约定沿用 `step-3.md`「3.8 起的共同约定」。

## 原因

Claude 用 `tools/acceptance/preview_seam.mjs` 在 WebKit（Tauri 在 macOS 上用的内核）里量了 Bill 采访的副本：正常每 33 毫秒出一帧，两个剪点处画面停了 366 毫秒和 383 毫秒，而且每次都在剪点上触发一次 `seeking`。预览只有一个 `<video>`，播到剪点时把它跳到下一段的入点，解码器要从关键帧重新解到入点，这段时间画面不动。

### P2.1 要求

Claude 在 WebKit 里一步步量出来的事实，做法都以它们为前提：

| 做法 | 量到的结果 |
|---|---|
| 一个 `<video>`，剪点处跳转（原来的做法） | 剪点处停 366～400 毫秒，旧片段越过出点 53～87 毫秒 |
| 下层的 `<video>` 提前跳到入点，暂停等着，到剪点再 `play()` | 从暂停到出第一帧要 250～430 毫秒。带声、静音、先播过一次、速度从 0 改成 1，结果都一样 |
| 下层用 `visibility: hidden` 藏起来 | WebKit 会让它放慢，到剪点时落后约 1.4 秒 |
| 改 `playbackRate` 校正，任意一次 | 每改一次卡约 300 毫秒：下层因此落后 0.3～0.4 秒，到剪点再改回原速又让画面停 300 毫秒 |
| 用 `currentTime` 跳转来校正 | 每次跳完要再等 150～350 毫秒才动起来，而且每次不一样，追不准 |
| 上层播放时，下层从「入点 − 剩余时间 + 提前量」静音开播，**等下层到了入点再切换** | 提前量 0.3 秒：新片段第一帧正好在入点，但旧片段停住等了 215～234 毫秒。提前量 0.53 秒：停顿 0～1 毫秒，最大帧间隔 49～83 毫秒，旧片段在出点前后 5 毫秒内结束。提前量 0.56 秒：旧片段少放 16～36 毫秒 |

做法：

1. 时间线预览有两个 `<video>`，用 `z-index` 叠在同一位置。同一时刻只有一个在上层，只有它出声。
   - 另一个在下层被盖住，静音，加 `data-preroll` 属性；在上层的那个不加。验收工具靠这个属性分辨哪个在上层。
   - 不用 `visibility: hidden`。
2. 正向、原生速度（现在 `native` 的条件）播放时，播放头离最上层视频轨的下一个片段边界不到 2 秒，就准备下层的那个：
   - 加载下一段的素材，同一个文件也照样准备；
   - 把 `currentTime` 设为「下一段入点 − 离边界的剩余时间 + 提前量」，按各自的速度换算成源时间；
   - 静音开播。
3. 提前量从 0.5 秒开始，每过一个剪点按实际情况调整一次，在本次打开 App 期间记住：
   - 加上旧片段停住等待的时长；
   - 减去旧片段没放完的时长；
   - 限制在 0.2～1.0 秒之间。
4. 准备好之后，不再改下层的 `playbackRate`，也不再赋值它的 `currentTime`。
5. 切换由下层的那个决定：
   - 它的 `currentTime` 到了下一段入点，就切换：把它换到上层，去掉 `data-preroll`，设好音量，取消静音；原来那个暂停，换到下层，加上 `data-preroll`。
   - 上层的那个到了出点而下层还没到入点时，上层先暂停，停在出点那一帧，等下层到了入点再切换。
   - 剪点处不对上层的 `<video>` 调用 `play()`，不赋值 `currentTime`，不改 `playbackRate`。
6. 下层的那个来不及跑起来时，照现在的做法切换，不能比现在更差。例如：
   - 用户刚跳到剪点前不到「提前量 + 0.3 秒」的地方；
   - 素材读得慢；
   - 下一段太短。
7. 播放头、时码和字幕跟着上层的那个走，和现在用 `currentTime` 推算的办法一致。停在出点那一帧等待时，播放头停在出点。
8. 下面这些行为不变：
   - 暂停、拖动播放头、倒放、`speed: "map"`、静帧和图片。
   - 用户拖动播放头或暂停时，停掉并丢弃下层的那个；重新播放时重新判断。
9. 声音只来自上层的那个，切换时不能两个同时出声。

### 验收

- 组件测试：用假的 `HTMLVideoElement` 验证切换顺序：
  - 提前 2 秒让下层的那个按提前量开播，之后不改它的速度和位置；
  - 下层到了入点才切换，上层先到出点时停在出点等待；
  - 提前量按停顿或少放的时长调整，并限制在范围内；
  - 剪点处上层的那个不 `play()`、不赋值 `currentTime`、不改 `playbackRate`；
  - 没准备好时退回旧做法；
  - 拖动播放头和暂停时丢掉下层的那个。
- Claude 在 Bill 采访的副本上运行 `tools/acceptance/preview_seam.mjs`，每个剪点都要满足：
  - 最大帧间隔不超过 2 帧（25p 下 100 毫秒以内）；
  - 上层的 `<video>` 在剪点处没有 `seeking`；
  - 新片段的第一帧离入点不超过 1 个素材帧，旧片段的最后一帧不越过出点 1 个素材帧以上。改动前的结果是 366 毫秒和 383 毫秒，两次都有 `seeking`。
- 交给 Bill 在 App 里实机看。
